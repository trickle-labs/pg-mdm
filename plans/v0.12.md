# v0.12 implementation plan: baseline admission and V1 reconciliation

## Outcome

Admit the released `pg_trickle` 0.105.2 package, replace the false scoped-preview
exactness claim, and turn the remaining V1 acceptance obligations into executable
evidence. Freeze `MDM-STEWARDSHIP/1` with pg-react before either project implements
the policy projection or intent API.

This release preserves PostgreSQL 18, trigger capture, full-entity MDM resolution,
and the current public MDM nouns and actions. It does not add policy tables,
automation writes, Delta V1, WAL capture, or prepared execution.

## Start gate

Start from pg-mdm `0.11.0` at `97b78c8`. Admit only this upstream artifact:

```text
version: 0.105.2
commit: 33df4cc91fda4fbadba79470347a714c8509703a
artifact: pg_trickle-0.105.2-pg18-linux-amd64.tar.gz
sha256: bf8d8dcff728a5cf9e09458b70f2c3ce2c92cc109f4e7c79ae2933ac8bb03416
```

The artifact must advertise stable, enabled `external_graph_refresh` major 1.
The advertised Delta and WAL capabilities remain unused. Missing upstream soak
evidence stays a recorded deployment limit rather than an MDM test pass.

## Dependency admission

- Update `DEPENDENCIES.md`, `tests/Dockerfile.e2e`, `src/version.rs`, the E2E image
  tag, and install documentation in one change.
- Verify the downloaded archive checksum before extraction. Make a checksum
  mismatch fail the image build.
- Run every existing public Graph V1, authorization, RLS, boundary, rollback,
  concurrency, lifecycle, restore, clone, and forbidden-private-API case against
  0.105.2.
- Add a populated pg-trickle 0.105.1 to 0.105.2 upgrade case. Keep the MDM entity,
  graph ownership, publications, grants, and consumer objects intact.
- Add the `0.11.0` to `0.12.0` MDM upgrade script and archive the generated
  `pg_mdm--0.12.0.sql`. Preserve all prior direct and sequential upgrade paths.

Do not loosen `integration_capabilities()` checks to admit the version. Admission
comes from the exact package passing the contract suite.

## Candidate insert regressions

Add both upstream-sensitive cases to `tests/e2e.sql`:

1. Insert several records into one bytea block-membership stage in one statement.
2. Insert several rows that create more than one candidate pair through the
   multi-row pair join in one statement.

For each case, refresh equivalent `AUTO` and `FULL` probe graphs from the same
committed source history. Compare complete rows, not counts, after insert, update,
delete, rollback, and retry. Record each node's reported strategy from
`node_results`.

Keep `FULL` on block-membership, statistics, overflow-guard, and candidate-pair
nodes in `src/graph_spec.rs` while they depend on forced-`FULL` stages. Remove a
fallback only after every stage passes insert, update, delete, rollback, and
retry in `AUTO`. Removing a fallback requires a new compiler version, a new
immutable artifact, and an adoption or rebuild test. Never edit an existing
artifact or silently change the strategy of an installed definition.

## Complete V1 preview behavior

The current `preview_entity()` sets `exact = true` for `scoped` without resolving
the requested subproblem. Remove that claim first. Then implement the three V1
modes through existing production components:

- `validation` validates the selected desired definition, artifact, source
  bindings, graph contract, and options. It returns `evidence_level = validation`
  and never reads terminal rows.
- `sampled` selects a deterministic bounded set by canonical source-record key.
  It runs the production terminal readers, pair-decision code, resolver, identity
  reconciler, golden selector, and review reconciler on that sample. It reports
  examples and observed work, with `evidence_level = sampled` and `exact = false`.
- `scoped` accepts only `source_record_ids` and `mdm_ids`. Expand `mdm_ids` to
  their active members, materialize all candidate and manual-constraint neighbors
  reachable within the configured closure limit, and resolve that induced
  subproblem through the same path. Return `evidence_level = exact_subjects` and
  `exact = true` only for the materialized subproblem. State that omitted records
  can change the full-entity result.

Reject unknown option keys, duplicate subjects, cross-entity records, an empty
scope, and a closure that exceeds `max_decision_closure`. Preview may record its
operation, but it must not refresh a graph, allocate durable IDs, advance a
frontier, change a definition, write a directive, or publish output.

Extract only the resolve-and-compare function needed by refresh and preview. Keep
SPI loading in `src/api/refresh.rs`; place the shared pure result construction in
one `src/evaluation.rs` module. A separate preview resolver is out of scope.

## V1 quality and operating evidence

Expand `tests/fixtures/organization_domain_v1.json` into tuning and held-out
partitions. Keep the format versioned and record label origin, permitted use, and
unresolved labels. Cover shared contacts, weak chains, authoritative conflicts,
deletion, reactivation, and identifiers that need business context.

Add one fixture runner that reports:

- candidate recall against labeled matching pairs;
- false merges, missed matches, and cluster errors;
- review count and reason distribution; and
- zero false merges for cannot-link, authoritative-conflict, and weak-chain
  safety cases.

The release owner freezes numeric thresholds before the final run. Keep tuning
cases out of the held-out result. A threshold change after the held-out run needs
a new reviewed run, not an edited expected file.

Extend the E2E report with source rows, block memberships and skew, repeated and
unique pairs, comparisons, component checks, memory, temporary bytes, output
rows and bytes, retained history, and transaction duration. Split time into graph
refresh, MDM resolution, and publication. Record the PostgreSQL build, CPU,
memory, storage, fixture digest, artifact digest, and upstream package digest.

## V1 acceptance register

Map every acceptance statement in `DESIGN_V1.md` to a test name and command.
For each entry record the commit, artifact and fixture digests, result, retained
log, owner, and whether the result blocks v1.0. A skipped blocking test remains
open. Historical release claims count only when their retained output proves the
current invariant.

Add missing executable cases to the nearest existing suite. Do not create a new
test framework. Use Rust tests for pure semantics and the Docker E2E path for
PostgreSQL, graph, role, upgrade, restore, and transaction behavior.

## Freeze `MDM-STEWARDSHIP/1`

Complete M0 with the pg-react R0 owner. Store the reviewed contract digest and
shared fixture digest in both repositories. Freeze these decisions before v0.13:

- `case_key` is a generated positive `bigint`, unique per `review_id`, never
  reused, and retained after resolution.
- `opened_at` is the `published_at` time of `opened_revision`. If that publication
  is unavailable, `opened_at` is null and automatic due-date actions are denied
  until an administrator records an audited backfill.
- Intent freshness pins `review_version`, `definition_version`, the latest
  successful observation's `publication_revision` and `stewardship_epoch`, an
  evidence-basis digest, and an action revision.
- The evidence-basis digest covers the case identity, status, reason, subjects,
  approved metadata, definition and artifact, source-boundary digest, observed
  decision epoch, and semantic versions.
- The action revision changes only when evidence or a routing control can change
  a policy result. Observation timestamps, receipt writes, and unrelated
  publication advances do not change it.
- The worker supplies a 32-byte request key, policy digest, and bounded text
  references for the policy revision, evaluation, and work item.
- Receipts and request bodies are retained without automatic deletion in the
  first integration. A later retention feature must preserve the agreed replay
  horizon or reject old requests as out of horizon.

Freeze exact table columns and the `submit_policy_intent` signature in the shared
contract fixture. v0.12 does not install those proposed objects.

The MDM-side proposal is in
[`contracts/MDM-STEWARDSHIP-1.json`](../contracts/MDM-STEWARDSHIP-1.json), SHA-256
`25dc84f8ae1f09374318b55be27540c3e195eb51cad7b9cd11fb135039e801db`. Its
canonical digest vectors are checked by `just test-stewardship-contract`. The
fixture defines `stewardship_epoch` as the `decision_epoch` observed by the last
successful publication. The concrete gaps for joint review are listed in
[`contracts/MDM-STEWARDSHIP-1-review.md`](../contracts/MDM-STEWARDSHIP-1-review.md).
Both project approvals remain pending; this draft is not jointly frozen and
its digest has not been adopted in `pg-react`.

## Implementation order

1. Pin and checksum 0.105.2, then pass the unchanged admission suite.
2. Add candidate insert regressions and decide whether each FULL fallback stays.
3. Repair preview labels, then implement sampled and scoped production-path work.
4. Build the V1 acceptance register and add missing blocking tests.
5. Freeze metrics and expand the organization corpus, then run the held-out and
   operating-envelope checks.
6. Approve the shared stewardship contract and fixtures with the React owner.
7. Package 0.12.0 and run upgrade, restore, clone, and cumulative CI.

## Exit criteria

- [x] The package and documentation pin the exact 0.105.2 artifact and checksum.
- [x] Public Graph V1 qualification, 0.105.1 upgrade, rollback, restore, and clone
  tests pass on that package.
- [x] Both candidate insert regressions compare exact AUTO and FULL rows and retain
  truthful `node_results`.
- [x] No preview mode claims more evidence than it computes.
- [x] V1 sampled and scoped previews run the production semantic path without
  publication or durable ID allocation.
- [ ] The held-out quality report and measured operating envelope have frozen
  thresholds, exact inputs, and retained results.
- [ ] Every V1 criterion has a test or an owned blocking entry for v1.0 in
  [`plans/v1-acceptance-register.md`](v1-acceptance-register.md).
- [ ] Both projects approve one exact `MDM-STEWARDSHIP/1` contract and fixture
  digest.
- [ ] Formatting, Clippy, Rust tests, pgrx tests, security checks, upgrade checks,
  archive comparison, package manifest, and Docker E2E pass.

## Deferred

Do not add the policy projection, policy intents, exact full-entity preview,
merge/split commands, semantic events, Delta V1, prepared execution, WAL capture,
or a user-facing evaluation product. v0.13 starts the first implementation of
the frozen stewardship contract.
