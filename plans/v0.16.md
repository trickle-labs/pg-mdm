# v0.16 implementation plan: exact entity preview and fixtures

## Outcome

Add `exact_entity` preview for one complete entity inside the measured synchronous
transaction envelope. Preview runs the production compiler, terminal readers,
resolver, identity reconciliation, golden selection, review reconciliation, and
output-schema comparison without publishing their result.

Add versioned pair, partition, forbidden-co-membership, and golden fixtures that
use the same evaluation path. This release has no runtime dependency on pg-react.

## Start gate

Require v0.12's truthful V1 preview modes and operating envelope. Follow v0.15 in
the recommended release sequence, but do not link exact preview to a React
binding. The admitted pg-trickle package needs only Graph V1. Prepared graph
generations and Delta V1 remain unnecessary.

## Release boundary

Extend the existing API rather than adding another preview entry point:

```sql
SELECT mdm.preview('customer', 'exact_entity', '{
  "max_facts": 100,
  "retain_for": "24 hours"
}'::jsonb);
```

The target is the entity's immutable desired definition and selected artifact.
An operator uses `mdm.create()` to store a proposed definition before preview.
Preview never activates that definition. Reject unknown options. Bound
`max_facts` to 1 through 500 and `retain_for` to 1 minute through 7 days.

Return these top-level fields:

```text
preview_id
preview_digest
evidence_level = exact_entity
exact = true
manifest
counts
membership_changes
identity_changes
golden_changes
review_changes
schema_changes
facts
facts_truncated
expires_at
```

Sort every array by canonical source-record key, MDM ID, field ordinal, issue
key, or fact order as applicable. Counts always describe the complete result.
Only detail arrays may be truncated.

## Isolated preview graph

Create a private preview graph for the desired artifact. Do not refresh or reuse
the active publication graph. The preview graph uses the same logical nodes,
refresh modes, contracts, and terminal schemas as publication.

Add one compiler artifact version that renders the source-record registry as a
physical input instead of embedding `mdm_graph.source_records` as an unchangeable
name. Normal publication renders the existing registry and must produce identical
terminal rows to the prior compiler version. Preview renders a run-scoped
registry keyed by `preview_id`.

The preview call performs this transaction:

1. Lock the entity for a stable desired version, active publication, decision
   epoch, role binding, and graph metadata.
2. Validate source privileges and scan active source keys under the selected
   execution role.
3. Populate run-scoped source identities and record handles. Reuse existing
   durable source-record IDs only as comparison inputs. Give unseen records
   preview-local handles.
4. Install the private graph through the public Graph V1 API with `EXTERNAL`
   orchestration and initialization disabled.
5. Strict-refresh the graph, require a proven source boundary, and load every
   terminal row through the production readers.
6. Evaluate and compare the complete result without calling publication writers.
7. Store the bounded preview result and manifest, then drop graph members in
   reverse topological order and remove run-scoped source rows.

If any step fails, PostgreSQL rolls back the graph, registry rows, preview row,
and operation record. If explicit graph cleanup fails, fail the statement so the
outer rollback removes the created objects. No successful call leaves a preview
graph installed.

Do not write `source_records`, `identity_registry`, `memberships`, aliases,
splits, golden provenance, reviews, directives, public outputs, entity versions,
decision epochs, publication revisions, or publication observations.

## Shared evaluation path

Move the pure work between terminal loading and persistence from
`persist_refresh_inner()` into `src/evaluation.rs`. Keep one input and one result:

```text
EvaluationInput
  source rows, pair decisions, manual constraints, old identity, old goldens,
  old reviews, definition, limits, target revision, and ID allocator

Evaluation
  resolution, next identity, goldens, reviews, semantic digest, and bounded facts
```

Refresh supplies the PostgreSQL UUID allocator and persists the result. Preview
supplies a deterministic allocator local to the manifest, then maps each new UUID
to `preview:1`, `preview:2`, and later handles in canonical component order before
serializing. A preview UUID must never appear in a public result or durable table.

Keep graph access, SPI readers, output DDL, and persistence outside the module.
Unit-test that refresh and preview inputs produce the same `Evaluation` after
normalizing local handles.

## Manifest and retained result

Add logged `mdm_internal.preview_runs` with the preview ID, kind, entity and
definition IDs, artifact and graph-binding digests, execution role name and OID,
source boundary and digest, base publication revision and result digest, decision
epoch, semantic versions, PostgreSQL identity, manifest JSON and digest, bounded
result JSON and digest, creator, creation time, and expiry time.

Preview rows are database-local and short-lived. Do not register them or the
run-scoped source registry for logical dump. Restore and clone invalidate every
old preview, even if a caller retained its digest.

Extend `mdm_admin.drop_entity()` to delete retained preview rows inside the
confirmed lifecycle transaction.

Use manifest format 1 and domain tag `pg_mdm/preview-manifest/v1`. Include only
inputs already available from the definition, artifact, source contract, Graph
V1 result, entity row, and semantic constants. Do not build the full optional V2
manifest catalogue.

`preview_digest` hashes the manifest digest, complete semantic result digest, and
preview kind. v0.17 may accept this digest only after rechecking every pinned
input. Expiry makes a run unusable for action authorization but does not change
the historical result before cleanup.

Add `mdm_admin.purge_previews(entity_name text, before timestamptz)`. Delete only
expired preview rows for the named entity. Require the entity execution role and
record one operation. No scheduler or automatic retention worker is added.

## Comparisons

Compare preview with the active publication and report:

- source-record membership additions, removals, and moves;
- entity creation, retirement, merge aliases, splits, and the V1 survivor choice;
- golden value, status, winning record, policy, and contributor changes;
- opened, reopened, changed, and resolved reviews;
- added output fields and compatible or incompatible type changes; and
- total source rows, pairs, accepted and rejected edges, components, identities,
  goldens, reviews, output rows, temporary bytes, and stage durations.

Digest protected values by default. Reuse the existing explanation permission
boundary for bounded facts. Exact preview must fail with a stable resource code
when source, pair, component, identity, output, time, memory, or temporary-storage
limits are exceeded. It must not fall back to sampling while retaining the exact
label.

## Regression fixtures

Add `tests/fixtures/preview_v2.json` with versioned cases for:

- expected pair evidence and classification;
- an exact expected partition;
- forbidden source-record co-membership;
- required survivor or anchor behavior; and
- expected golden value status and provenance class.

Keep fixture subjects as source name plus canonical source key. Resolve their
durable or preview-local handles inside the runner. A fixture never creates a
steward decision.

Run fixtures against both the active and desired definition through the shared
evaluation path. Report the fixture population, passed and failed labels, coverage,
and separate high-risk conflict coverage. Precision or recall is reported only
when the fixture supplies a complete denominator.

## File layout

```text
src/
  evaluation.rs           shared non-publishing semantic evaluation
  preview.rs              manifest, handles, comparison, and bounded result
  api/refresh.rs           refresh orchestration using Evaluation
  api/preview.rs           exact preview graph and public wrapper
  graph_spec.rs            selectable source-record registry input
  schema.rs                preview run and run-scoped registry tables
  error.rs                 preview manifest, expiry, and resource codes
tests/
  preview_tests.rs         pure comparison and fixture runner
  fixtures/preview_v2.json
  e2e_preview.sql          graph isolation, parity, rollback, and permissions
```

Move the existing V1 preview code from `api/refresh.rs` to `api/preview.rs` only
when exact preview makes the original file harder to review. Do not add a general
job system or preview cache.

## Implementation order

1. Extract `Evaluation` and prove refresh results do not change.
2. Freeze manifest, preview handle, comparison, and fixture vectors.
3. Add the run-scoped registry and parameterized compiler artifact.
4. Install, refresh, read, and clean up the isolated preview graph.
5. Persist the bounded result and implement `exact_entity` comparison.
6. Run labeled fixtures through the same path.
7. Add the `0.15.0` to `0.16.0` migration, archive, documentation, and cumulative
   qualification.

## Test matrix

| Case | Required result |
|---|---|
| Desired definition differs from active | Exact isolated comparison; active graph unchanged |
| Same manifest followed by refresh | All semantic and schema results match |
| New source records | Preview-local handles only; refresh later allocates durable IDs |
| Source write after preview boundary | Excluded from preview and forces a later manifest |
| Role, RLS, definition, decision, or graph change | Retained preview cannot authorize later work |
| Merge and split caused by definition | Exact members and V1 survivor choices match refresh |
| Rejected definition or graph contract | No preview graph or result survives |
| Resource limit | Stable failure; no sampled or partial exact result |
| Output schema change | Exact compatible or blocking effect |
| Cleanup failure | Whole preview rolls back |
| Purge | Only expired named-entity results are removed |
| Fixture failure | Exact label and reason identify the mismatched subject |

## Exit criteria

- [ ] `exact_entity` uses all production semantic components and a separate Graph
  V1 graph.
- [ ] Preview and subsequent refresh match from the same manifest.
- [ ] No successful or failed preview changes publication, identity, stewardship,
  source-record, or active graph state.
- [ ] Every new identity is exposed only through a preview-local handle.
- [ ] Every exact result pins the required manifest fields and expires.
- [ ] Oversized work fails explicitly without a partial exact result.
- [ ] All four fixture kinds run through the shared production evaluation path.
- [ ] Upgrade, restore, security, package, and cumulative E2E checks pass.

## Deferred

Do not add inference, prepared preview, interactive diagnostics, user-defined
metrics, event simulation, or a generic manifest system. v0.17 adds exact action
preview only for merge and complete split.
