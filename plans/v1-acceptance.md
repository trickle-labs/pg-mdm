The normative criteria are in [DESIGN_V1.md](../DESIGN_V1.md#17-acceptance-criteria), especially its invariants in section 16.

## Release blockers tracked outside the tests

- **Preview evidence:** validation, sampled, and scoped modes now share refresh's resolve-and-compare path; scoped exactness is limited to a bounded induced subproblem and previews do not persist IDs or publish. The SQL read-only assertions are new and need the Docker E2E run. Later source writes may still be pending because preview uses the last successful publication.
- **Shared stewardship contract:** the MDM-side M0 fixture is still a proposed contract. React owner approval and matching fixture/digest adoption in `pg-react` remain external handoffs; a local draft cannot claim joint approval.
- **Dependency admission:** the build pins the exact 0.105.2 artifact. Release evidence still requires passing Docker E2E with existing MDM entities/publications and package/archive checks; an upstream release and checksum are not test evidence.
- **Retained evidence:** preserve exact package and fixture digests, commands, CI results, upgrade/restore evidence, and operating measurements together. This register intentionally records no pass claims because those outputs are not checked in.

The v1.0 gate remains blocked until every acceptance row has reviewed executable evidence and the blockers above are closed. V2-only exclusions remain governed by [DESIGN_V1.md](../DESIGN_V1.md#17-acceptance-criteria) and are not treated as V1 gaps here.
