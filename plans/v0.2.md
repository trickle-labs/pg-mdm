# v0.2 implementation plan: definitions and validation

## Outcome

Store immutable entity definitions, reject unsafe source contracts, compile a deterministic private-graph specification as JSON, and expose the developmental `mdm.create()` and `mdm.describe()` actions. Equivalent definitions remain no-ops. Concurrent writers cannot overwrite each other.

Graph V1 remains disabled in the pinned `pg_trickle` release. This release stores graph specifications but does not create stream tables or call a Graph V1 mutation API.

## Prerequisites and dependency changes

Start from the v0.1 release and keep its exact PostgreSQL, `pgrx`, and `pg_trickle` pins.

No new runtime crate is needed. Use `serde_json` for the stored form, `BTreeMap` and `BTreeSet` for canonical ordering, and `sha2` for the digest. Do not add a configuration framework or a JSON canonicalization crate.

Add the migration `sql/pg_mdm--0.1.0--0.2.0.sql`. Preserve `sql/archive/pg_mdm--0.1.0.sql`, generate `sql/archive/pg_mdm--0.2.0.sql`, and test a real `ALTER EXTENSION pg_mdm UPDATE TO '0.2.0'`.

Keep one authoritative JSON definition per version. Do not normalize the five nouns into five catalog table families. The compiler can deserialize the JSON into Rust structs when it needs typed access.

## Schema skeleton

Add two internal tables:

```sql
CREATE TABLE mdm_internal.entities (
    entity_id uuid PRIMARY KEY DEFAULT uuidv7(),
    entity_name name NOT NULL UNIQUE,
    execution_role oid NOT NULL,
    desired_version bigint NOT NULL CHECK (desired_version > 0),
    active_version bigint,
    created_at timestamptz NOT NULL DEFAULT statement_timestamp(),
    created_by oid NOT NULL,
    CHECK (active_version IS NULL OR active_version > 0)
);

CREATE TABLE mdm_internal.definitions (
    entity_id uuid NOT NULL REFERENCES mdm_internal.entities(entity_id),
    definition_version bigint NOT NULL CHECK (definition_version > 0),
    parent_version bigint,
    user_definition jsonb NOT NULL,
    expanded_definition jsonb NOT NULL,
    logical_candidate_plan jsonb NOT NULL,
    graph_spec jsonb NOT NULL,
    graph_spec_digest bytea NOT NULL CHECK (octet_length(graph_spec_digest) = 32),
    semantic_manifest jsonb NOT NULL,
    semantic_digest bytea NOT NULL CHECK (octet_length(semantic_digest) = 32),
    comment text,
    created_at timestamptz NOT NULL DEFAULT statement_timestamp(),
    created_by oid NOT NULL,
    PRIMARY KEY (entity_id, definition_version),
    UNIQUE (entity_id, semantic_digest),
    CHECK (parent_version IS NULL OR parent_version < definition_version)
);
```

`active_version` stays null through v0.6. Live activation belongs to the publication releases. Revoke all access to both tables from `PUBLIC`.

The `semantic_manifest` names every pinned semantic input available at this stage:

```json
{
  "format_version": 1,
  "engine_version": 1,
  "source_key_encoding": 2,
  "cleaners": {
    "company_name": 1,
    "email": 1,
    "tax_id": 1
  },
  "comparators": {
    "exact": 1,
    "normalized_levenshtein": 1
  },
  "pair_decision_policy": 1,
  "clustering_policy": 1,
  "stable_id_policy": 1,
  "golden_policies": {
    "first_non_null": 1,
    "latest": 1,
    "most_common": 1,
    "prefer_source": 1
  },
  "required_pg_trickle_capability": {
    "name": "external_graph_refresh",
    "major": 1,
    "minimum_minor": 0
  }
}
```

Hash the canonical expanded definition, logical candidate plan, graph-spec digest, and semantic manifest. Database-local graph contract generations and digests do not exist yet; v0.8 stores those in a separate graph binding without rewriting this immutable definition.

## API skeleton

Use JSONB as the constructor interchange type. The constructors validate one noun and return canonical JSONB. `mdm.entity()` checks references across the full value.

```sql
mdm.source(
    name name,
    relation regclass,
    source_id name[],
    mode text,
    fields jsonb,
    row_changed_at name DEFAULT NULL,
    soft_delete_when jsonb DEFAULT NULL,
    authority jsonb DEFAULT '{}'::jsonb
) RETURNS jsonb

mdm.field(
    name name,
    type text,
    cleaner text,
    cleaner_options jsonb DEFAULT '{}'::jsonb,
    display text DEFAULT 'masked'
) RETURNS jsonb

mdm.match(
    name name,
    fields name[],
    comparison text,
    strength text,
    evidence_group name,
    threshold integer DEFAULT NULL,
    candidate jsonb DEFAULT NULL
) RETURNS jsonb

mdm.golden_value(
    field name,
    policy text,
    sources name[] DEFAULT NULL
) RETURNS jsonb

mdm.entity(
    name name,
    sources jsonb[],
    fields jsonb[],
    matches jsonb[],
    golden_values jsonb[],
    preset text DEFAULT NULL,
    limits jsonb DEFAULT '{}'::jsonb,
    execution_role regrole DEFAULT NULL
) RETURNS jsonb

mdm.create(
    definition jsonb,
    expected_version bigint DEFAULT NULL,
    comment text DEFAULT NULL
) RETURNS TABLE (
    operation_id uuid,
    entity_name name,
    desired_version bigint,
    changed boolean,
    semantic_digest bytea
)

mdm.describe(
    entity_name name,
    format text DEFAULT 'summary'
) RETURNS jsonb
```

`execution_role = NULL` means the invoking session role, captured before entering security-definer code. Store that role's OID in `entities`; future defining queries always run as that role and fail if its source access has been revoked. `format = 'definition'` returns portable canonical JSON without OIDs, generated relation names, or physical plan choices. `format = 'summary'` returns desired and active versions, digests, capability state, validated source metadata, and blocking errors. It does not claim live graph contracts or graph health before v0.8.

Resolve a bare built-in preset name to its current version, then store the versioned name in the expanded definition. Keep preset expansion in `presets.rs`; a preset change always receives a new version and never changes an existing expanded definition.

Before the public V1 API freezes, keep these signatures marked developmental in `README.md` and `CHANGELOG.md`.

## Validation contract

Run all validation before inserting either catalog row:

1. Require UTF-8 database encoding.
2. Require a unique entity name that is safe as a PostgreSQL identifier.
3. Resolve the execution role and require `SELECT` on each source relation and mapped column.
4. Accept only local ordinary or partitioned tables. Reject views, materialized views, foreign tables, and temporary tables.
5. Accept `tracked` and `soft_delete` modes only. For `soft_delete`, accept only typed `is_true` or `is_not_null` column predicates. Do not accept raw SQL.
6. Resolve each source key to either a primary key or an immediate, valid, non-partial, non-expression unique index.
7. Require each key column to be `NOT NULL`, or require the chosen index to use `NULLS NOT DISTINCT`.
8. Resolve every field mapping and require the mapped type to match the logical field or an explicitly supported lossless coercion.
9. Require unique names within each noun list and valid references between lists.
10. Reject a supporting match with a candidate channel.
11. Require a complete candidate channel for every fuzzy identity or strong match.
12. Reject evidence groups whose field lineage overlaps across different group names.
13. Validate golden-policy inputs, source priorities, and `latest` timestamp mappings.
14. Expand defaults and the optional built-in preset before computing digests.
15. Read capability state through the v0.1 adapter and record it. Do not require enabled Graph V1 yet.

Use PostgreSQL catalog tables only for PostgreSQL relation validation. Never inspect a private `pg_trickle` relation.

## Canonicalization and graph specification

Sort sources, fields, matches, and golden values by their unique names. Preserve arrays whose order has meaning, including composite key columns and `prefer_source` priorities. Reject duplicate JSON object keys during constructor input handling where PostgreSQL has not already collapsed them.

Compile stable logical stages such as:

```text
records/crm
records/registry
normalized/email
normalized/name
blocks/same_email
pairs/customer
evidence/customer
golden/customer
```

Each graph-spec node stores its logical ID, dependencies, output columns, canonical defining SQL, initialization flag `false`, and orchestration mode `EXTERNAL`. Generated database relation names remain absent. v0.8 maps logical IDs to private relation names and asks `pg_trickle` for the real member and graph contracts.

## Implementation order

1. Add typed definition structs and noun constructors.
2. Add local and cross-reference validation.
3. Add source catalog and execution-role checks.
4. Add default expansion, canonicalization, and digests.
5. Compile the deterministic graph specification without executing it.
6. Add `entities` and `definitions`, then implement optimistic writes.
7. Add `mdm.describe()` formats and privilege grants.
8. Add the 0.1.0 to 0.2.0 migration and upgrade test.

For a new entity, require `expected_version IS NULL`. For an existing entity, require `expected_version = desired_version`, including semantic no-ops. Lock the entity row before comparing. Insert the next version only when the semantic digest differs.

## Test matrix

| Level | Case | Expected result |
|---|---|---|
| Unit | Reorder sources, fields, matches, and JSON object keys | Semantic and graph-spec digests stay equal |
| Unit | Change a source-priority list, threshold, cleaner version, or candidate predicate | Semantic digest changes |
| Unit | Re-submit the same expanded definition | `changed = false`; no version row is added |
| Unit | Compile the same definition repeatedly | Graph-spec bytes and digest stay equal |
| Unit | Overlapping lineage in separate evidence groups | Validation rejects the definition |
| End to end | Use a primary key, composite key, and valid unique index | Source-key validation succeeds |
| End to end | Use a nullable ambiguous key, partial index, expression index, or deferred constraint | Validation fails without catalog writes |
| End to end | Use a view, materialized view, foreign table, or temporary table | Validation fails with a stable code |
| End to end | Revoke source `SELECT` from the execution role | Creation fails before the version write |
| End to end | Exercise row-level security under the captured execution role | Validation observes that role's access |
| End to end | Submit two updates with the same `expected_version` | One succeeds; one gets a version conflict |
| End to end | Raise an injected failure after entity insert | The entity, definition, and operation roll back |
| End to end | Call `describe(..., 'definition')` and feed the result to `create` | The definition round-trips without private names |
| End to end | Upgrade an installed 0.1.0 database | Existing foundation state survives and new tables exist |
| Security | Call constructors and actions through hostile `search_path` objects | Fixed-path functions use extension objects only |

Run the v0.1 commands plus:

```text
just test-definitions
just test-upgrade from=0.1.0
```

## Exit criteria

- [ ] All five noun constructors reject invalid local input and return canonical JSONB for valid input.
- [ ] `mdm.create()` stores exactly one immutable row for a changed definition.
- [ ] Equivalent definitions remain no-ops under input and JSON-key reordering.
- [ ] `expected_version` prevents concurrent overwrite and leaves no partial state.
- [ ] Every supported and rejected source-key shape has an end-to-end test.
- [ ] `mdm.describe(..., 'definition')` round-trips into the same semantic and graph-spec digests.
- [ ] The graph specification contains `EXTERNAL` and `initialize = false`, but no graph object exists in PostgreSQL.
- [ ] Disabled Graph V1 is visible in `describe` and does not block definition storage.
- [ ] The 0.1.0 to 0.2.0 extension upgrade passes.
- [ ] The full v0.1 test matrix still passes.

After this release, revise the estimates for v0.3 through v0.7 from measured implementation and review time.

## Deferred

Do not execute graph SQL, allocate source-record IDs, normalize values, enumerate candidates, resolve pairs, or create public output tables. Those changes belong to later releases.
