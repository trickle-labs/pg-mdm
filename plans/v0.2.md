# v0.2 implementation plan: definitions and validation

## Outcome

Store immutable entity definitions, reject unsafe source contracts, reserve output names, compile deterministic append-only graph artifacts, and expose the developmental `mdm.create()` and `mdm.describe()` actions. A submission equal to the current desired definition is a no-op. Concurrent writers cannot overwrite each other.

Graph V1 remains disabled in the pinned `pg_trickle` release. This release stores graph specifications but does not create stream tables or call a Graph V1 mutation API.

## Prerequisites and dependency changes

Start from the v0.1 release and keep its exact PostgreSQL, `pgrx`, and `pg_trickle` pins.

No new runtime crate is needed. Use `serde_json` for the stored form, `BTreeMap` and `BTreeSet` for canonical ordering, and `sha2` for the digest. Do not add a configuration framework or a JSON canonicalization crate.

Add the migration `sql/pg_mdm--0.1.0--0.2.0.sql`. Preserve `sql/archive/pg_mdm--0.1.0.sql`, generate `sql/archive/pg_mdm--0.2.0.sql`, and test a real `ALTER EXTENSION pg_mdm UPDATE TO '0.2.0'`.

## Schema skeleton

Add the durable definition, source-identity, namespace, and artifact tables:

```sql
CREATE TABLE mdm_internal.entities (
    entity_id uuid PRIMARY KEY DEFAULT uuidv7(),
    entity_name name NOT NULL UNIQUE,
    execution_role_name text NOT NULL,
    desired_version bigint NOT NULL CHECK (desired_version > 0),
    active_version bigint,
    created_at timestamptz NOT NULL DEFAULT statement_timestamp(),
    created_by_name text NOT NULL,
    CHECK (active_version IS NULL OR active_version > 0)
);

CREATE TABLE mdm_internal.definitions (
    entity_id uuid NOT NULL REFERENCES mdm_internal.entities(entity_id),
    definition_version bigint NOT NULL CHECK (definition_version > 0),
    parent_version bigint,
    user_definition jsonb NOT NULL,
    expanded_definition jsonb NOT NULL,
    logical_candidate_plan jsonb NOT NULL,
    semantic_manifest jsonb NOT NULL,
    definition_digest bytea NOT NULL CHECK (octet_length(definition_digest) = 32),
    comment text,
    created_at timestamptz NOT NULL DEFAULT statement_timestamp(),
    created_by_name text NOT NULL,
    PRIMARY KEY (entity_id, definition_version),
    CHECK (parent_version IS NULL OR parent_version < definition_version)
);

CREATE TABLE mdm_internal.source_identities (
    source_identity_id uuid PRIMARY KEY DEFAULT uuidv7(),
    entity_id uuid NOT NULL REFERENCES mdm_internal.entities(entity_id),
    source_name name NOT NULL,
    relation_name text NOT NULL,
    key_contract jsonb NOT NULL,
    identity_digest bytea NOT NULL CHECK (octet_length(identity_digest) = 32),
    UNIQUE (entity_id, source_name)
);

CREATE TABLE mdm_internal.source_bindings (
    source_identity_id uuid PRIMARY KEY
        REFERENCES mdm_internal.source_identities(source_identity_id),
    relation_oid oid NOT NULL,
    binding_fingerprint jsonb NOT NULL,
    bound_at timestamptz NOT NULL DEFAULT statement_timestamp()
);

CREATE TABLE mdm_internal.output_names (
    output_name name PRIMARY KEY,
    entity_id uuid NOT NULL REFERENCES mdm_internal.entities(entity_id),
    output_kind text NOT NULL CHECK (output_kind IN ('entity', 'members', 'review')),
    UNIQUE (entity_id, output_kind)
);

CREATE TABLE mdm_internal.execution_role_bindings (
    entity_id uuid PRIMARY KEY REFERENCES mdm_internal.entities(entity_id),
    role_oid oid NOT NULL,
    bound_at timestamptz NOT NULL DEFAULT statement_timestamp()
);

CREATE TABLE mdm_internal.definition_artifacts (
    artifact_id uuid PRIMARY KEY DEFAULT uuidv7(),
    entity_id uuid NOT NULL,
    definition_version bigint NOT NULL,
    compiler_version integer NOT NULL CHECK (compiler_version > 0),
    artifact_format_version integer NOT NULL CHECK (artifact_format_version > 0),
    artifact_bytes bytea NOT NULL,
    artifact_digest bytea NOT NULL CHECK (octet_length(artifact_digest) = 32),
    created_at timestamptz NOT NULL DEFAULT statement_timestamp(),
    created_by_name text NOT NULL,
    UNIQUE (entity_id, definition_version, compiler_version, artifact_digest),
    FOREIGN KEY (entity_id, definition_version)
        REFERENCES mdm_internal.definitions(entity_id, definition_version)
);
```

`active_version` stays null through v0.6. Live activation belongs to the publication releases. Revoke all access to these tables from `PUBLIC`.

`source_identities` stores portable frozen contracts. `source_bindings` stores database-local relation OIDs and is derived. Exclude it from logical dumps and rebuild it only through an explicit administrator-approved rebind that verifies the relation name, key contract, type and collation fingerprint, privileges, and row-security behavior.

`execution_role_bindings` is also derived and excluded from logical dumps. Establish its role OID at creation and compare both the stored name and OID before every entity action that requires the execution role. A same-name role replacement, missing binding, or incompatible role attribute fails closed until an administrator explicitly rebinds it. Rebinding verifies current privileges and source visibility; it cannot authorize an otherwise forbidden role.

Register `entities`, `definitions`, `source_identities`, `output_names`, and `definition_artifacts` with `pg_catalog.pg_extension_config_dump()`. Their foreign keys form an acyclic restore order. v0.1 already registers `operations`; do not register `source_bindings` or `execution_role_bindings`.

The `semantic_manifest` names every pinned semantic input available at this stage:

```json
{
  "format_version": 1,
  "engine_version": 1,
  "source_key_encoding": 2,
  "cleaners": {
    "company_name": 1,
    "email": 1,
    "tax_id": 1
  },
  "comparators": {
    "exact": 1,
    "normalized_levenshtein": 1
  },
  "pair_decision_policy": 1,
  "clustering_policy": 1,
  "stable_id_policy": 1,
  "golden_policies": {
    "first_non_null": 1,
    "latest": 1,
    "most_common": 1,
    "prefer_source": 1
  },
  "required_pg_trickle_capability": {
    "name": "external_graph_refresh",
    "major": 1,
    "minimum_minor": 0
  }
}
```

Compute three domain-separated identities:

1. `definition_digest` hashes the tag `pg_mdm/definition/v1`, the canonical expanded definition, logical candidate plan, and semantic manifest. It contains portable logical semantics only.
2. `artifact_digest` hashes the tag `pg_mdm/artifact/v1`, `definition_digest`, compiler and artifact format versions, exact generated graph-spec bytes, and versioned terminal-relation schemas.
3. v0.8 adds `graph_binding_digest`, which hashes the tag `pg_mdm/graph-binding/v1`, `artifact_digest`, the database-local graph generation, execution-role and source bindings, member contracts, and canonical graph digest.

Define the length prefixes, integer byte order, JSON canonicalization, and array ordering once in the fixture contract. An extension upgrade may add a new immutable artifact for an existing definition version. It never edits the definition row or an older artifact.

Record all semantics needed by an executable stage before accepting its artifact, including cleaner bounds, candidate predicates and limits, comparator thresholds and work limits, resolver limits, and policy versions. Development artifacts explicitly mark unfinished stages non-executable. Later releases may attach implementations of already pinned semantics. If they introduce a missing default, option, or policy contract, require a new `mdm.create()` definition version before that stage can execute. Never fill a historical definition from the compiler's current defaults. Keep logical templates and binding parameters separate so newly allocated entity IDs, source IDs, and local OIDs do not enter the portable artifact digest.

## API skeleton

Use JSONB as the constructor interchange type. The constructors validate one noun and return canonical JSONB. `mdm.entity()` checks references across the full value.

```sql
mdm.source(
    name text,
    relation regclass,
    source_id text[],
    mode text,
    fields jsonb,
    row_changed_at text DEFAULT NULL,
    soft_delete_when jsonb DEFAULT NULL,
    authority jsonb DEFAULT '{}'::jsonb
) RETURNS jsonb

mdm.field(
    name text,
    type text,
    cleaner text,
    cleaner_options jsonb DEFAULT '{}'::jsonb,
    display text DEFAULT 'masked'
) RETURNS jsonb

mdm.match(
    name text,
    fields text[],
    comparison text,
    strength text,
    evidence_group text,
    threshold integer DEFAULT NULL,
    candidate jsonb DEFAULT NULL
) RETURNS jsonb

mdm.golden_value(
    field text,
    policy text,
    sources text[] DEFAULT NULL
) RETURNS jsonb

mdm.entity(
    name text,
    sources jsonb[],
    fields jsonb[],
    matches jsonb[],
    golden_values jsonb[],
    preset text DEFAULT NULL,
    limits jsonb DEFAULT '{}'::jsonb,
    execution_role text DEFAULT NULL
) RETURNS jsonb

mdm.create(
    definition jsonb,
    expected_version bigint DEFAULT NULL,
    comment text DEFAULT NULL
) RETURNS TABLE (
    operation_id uuid,
    entity_name name,
    desired_version bigint,
    changed boolean,
    definition_digest bytea,
    artifact_digest bytea
)

mdm.describe(
    entity_name text,
    format text DEFAULT 'summary'
) RETURNS jsonb
```

`mdm.create()` and every future source-facing action are `SECURITY INVOKER`. `execution_role = NULL` means `current_user`. A non-null value must name `current_user` exactly. For delegated execution, `session_user` must have PostgreSQL's `SET` option and the client must run `SET ROLE` before calling `mdm.create()`. A caller cannot nominate a role it has not selected. Reject a superuser, a role with `BYPASSRLS`, and the extension owner. Store the portable role name and the derived OID binding; verify both whenever source SQL runs. Updating an existing entity must first authorize against its existing binding, before considering the submitted definition.

Narrow `SECURITY DEFINER` helpers perform catalog writes after invoker validation. They use the v0.1 fixed path and never run source SQL or change role. `format = 'definition'` returns portable canonical JSON without OIDs, generated relation names, or physical plan choices. `format = 'summary'` returns desired and active versions, the definition and artifact digests, capability state, validated source metadata, and blocking errors. It reports the graph-binding digest only after v0.8 and only to authorized operators.

Reuse the v0.1 authorization boundary. Each callable helper checks direct calls, authenticates the caller from PostgreSQL context, authorizes the existing entity, and validates its catalog-write arguments under the entity lock. It cannot trust a caller-supplied actor, execution role, entity ID, or claim that the public wrapper validated a definition. Configurators receive no direct DML rights on internal tables.

Qualify RLS visibility as part of source validation. Test policy changes, role-membership changes, session-dependent predicates, and policy lookup-table changes without source DML. Accept a case only when its visibility is pinned or changes invalidate the graph and require complete recomputation. Reject unsupported dependencies explicitly. The SQL fixture path proves selected-role visibility; the v0.8 admission suite must separately prove equivalent behavior through `pg_trickle`.

A source field mapping is either a value-column name or an object with `value` and `state` column names. The optional state column accepts only `present`, `unknown`, or `redacted`. SQL `NULL` with `present` means `absent`; `unknown` and `redacted` ignore the value column. Reject magic-string encodings and do not retain a redacted value.

Resolve a bare built-in preset name to its current version, then store the versioned name in the expanded definition. Keep preset expansion in `presets.rs`; a preset change always receives a new version and never changes an existing expanded definition.

Before the public V1 API freezes, keep these signatures marked developmental in `README.md` and `CHANGELOG.md`.

## Validation contract

Run all validation before inserting either catalog row:

1. Require UTF-8 database encoding.
2. Keep identifier inputs as `text` until validation completes. Derive the entity, members, and review table names, then require each complete UTF-8 name to fit within 63 bytes without truncation.
3. Reject output-name collisions after PostgreSQL identifier folding and reserve all three names in `output_names` in the same transaction as the entity row. Reject a conflicting object already in `mdm_out`.
4. Reject golden fields named `mdm_id`, `member_count`, `has_review`, `last_change_revision`, or a PostgreSQL system column: `tableoid`, `xmin`, `cmin`, `xmax`, `cmax`, or `ctid`.
5. Require the requested execution role to equal the invoker's `current_user`. Verify the authenticated `session_user`, selected role, role attributes, and delegation state separately.
6. Resolve the execution role and require relation and column `SELECT` on each source. Evaluate validation queries under that role with row-level security enabled. Reject a role that bypasses the intended policy because it owns a relation unless the relation uses `FORCE ROW LEVEL SECURITY`.
7. Accept only local ordinary or partitioned tables. Reject views, materialized views, foreign tables, and temporary tables.
8. Accept `tracked` and `soft_delete` modes only. For `soft_delete`, accept only typed `is_true` or `is_not_null` column predicates. Do not accept raw SQL.
9. Resolve each source key to either a primary key or an immediate, valid, non-partial, non-expression unique index.
10. Require each key column to be `NOT NULL`, or require the chosen index to use `NULLS NOT DISTINCT`.
11. For a new source name, allocate `source_identity_id` and freeze the qualified relation name, relation OID binding, key columns, key types, collations, and source-key encoding. For an existing name, reject any change to that identity contract. Relation replacement is not definition evolution.
12. Resolve every value and state mapping. Require the mapped type to match the logical field or an explicitly supported lossless coercion, and validate the state-column tags.
13. Require unique names within each noun list and valid references between lists.
14. Reject a supporting match with a candidate channel.
15. Require a complete candidate channel for every fuzzy identity or strong match.
16. Reject evidence groups whose field lineage overlaps across different group names.
17. Validate golden-policy inputs, source priorities, and `latest` timestamp mappings.
18. Expand defaults and the optional built-in preset before computing digests.
19. Read capability state through the v0.1 adapter and record it. Do not require enabled Graph V1 yet.

Use PostgreSQL catalog tables only for PostgreSQL relation validation. Never inspect a private `pg_trickle` relation.

## Canonicalization and graph specification

Sort sources, fields, matches, and golden values by their unique names. Preserve arrays whose order has meaning, including composite key columns and `prefer_source` priorities. Reject duplicate JSON object keys during constructor input handling where PostgreSQL has not already collapsed them. The canonical byte encoder uses explicit type tags and lengths; it never relies on `jsonb` display order.

Compile stable logical stages such as:

```text
records/crm
records/registry
normalized/email
normalized/name
blocks/same_email
pairs/customer
evidence/customer
golden/customer
```

Each graph-spec node stores its logical ID, dependencies, versioned output schema, canonical defining SQL, initialization flag `false`, and orchestration mode `EXTERNAL`. Generated database relation names remain absent. Generated SQL binds values, quotes identifiers, schema-qualifies objects, and permits one allowlisted `SELECT` shape per stage. v0.3 through v0.5 attach progressively executable artifact versions to the same immutable definition rows. v0.8 maps a selected complete artifact to private relation names and asks `pg_trickle` for the real member and graph contracts.

## Implementation order

1. Add typed definition structs and noun constructors.
2. Add local and cross-reference validation.
3. Add source catalog and execution-role checks.
4. Add default expansion, canonicalization, and definition digests.
5. Compile the deterministic graph specification without executing it.
6. Add the durable tables, derived source binding, dump registration, and optimistic writes.
7. Add transactional output-name reservation.
8. Add `mdm.describe()` formats and privilege grants.
9. Add the 0.1.0 to 0.2.0 migration, upgrade test, and clean logical restore test.

For a new entity, require `expected_version IS NULL`. For an existing entity, require `expected_version = desired_version`, including no-ops. Lock the entity row before comparing the proposed definition digest with the current desired row. If they match, return `changed = false`. Otherwise insert the next version and its compiler artifact even when an older historical version has the same digest. Thus A→B→A succeeds and creates version 3.

## Test matrix

| Level | Case | Expected result |
|---|---|---|
| Unit | Reorder sources, fields, matches, and JSON object keys | Definition and artifact digests stay equal |
| Unit | Change a source-priority list, threshold, cleaner version, or candidate predicate | Definition digest changes |
| Unit | Re-submit the same expanded definition | `changed = false`; no version row is added |
| Unit | Submit definitions A→B→A | Three version rows exist; versions 1 and 3 may share a definition digest |
| Unit | Compile the same definition repeatedly | Graph-spec bytes and digest stay equal |
| Unit | Dispatch a stored cleaner or comparator version after a registry upgrade | The artifact selects the recorded implementation, never the current default |
| Unit | Compile an old definition missing a later semantic limit or policy input | Its digest remains unchanged; the stage is non-executable until an explicit new definition supplies the input |
| Unit | Bind one portable artifact to different allocated entity and source IDs | Definition and artifact digests stay equal; only binding data differs |
| Unit | Overlapping lineage in separate evidence groups | Validation rejects the definition |
| End to end | Use a primary key, composite key, and valid unique index | Source-key validation succeeds |
| End to end | Use a nullable ambiguous key, partial index, expression index, or deferred constraint | Validation fails without catalog writes |
| End to end | Use a view, materialized view, foreign table, or temporary table | Validation fails with a stable code |
| End to end | Revoke source `SELECT` from the execution role | Creation fails before the version write |
| Security | Nominate a more privileged role without first selecting it | Creation fails before source access or catalog writes |
| Security | Use `SET ROLE` through an authorized membership | Validation runs as the selected role and records the authenticated actor separately |
| Security | Exercise row-level security under the selected execution role | Validation sees only policy-visible rows |
| Security | Revoke source access or role membership after definition creation | The next validation or execution fails before mutation |
| Security | Drop and recreate the execution role under the same name | The changed OID is rejected until explicit administrator rebinding |
| Security | Call a catalog helper directly with forged actor, entity, or validation arguments | No protected write occurs; another execution role's entity cannot be changed |
| Security | Change RLS visibility without source-row changes | Supported changes invalidate prior evidence; unsupported policy dependencies fail closed |
| Security | Raise an error after source validation | Role, search path, and configuration context are unchanged |
| End to end | Submit two updates with the same `expected_version` | One succeeds; one gets a version conflict |
| End to end | Raise an injected failure after entity insert | The entity, definition, and operation roll back |
| End to end | Call `describe(..., 'definition')` and feed the result to `create` | The definition round-trips without private names |
| End to end | Use `customer` and `customer_members`, a multibyte boundary name, or a suffixed name over 63 bytes | Output reservation rejects every collision or truncation case |
| End to end | Use a golden field that collides with metadata or a system column | Validation rejects it before reservation |
| End to end | Upgrade an installed 0.1.0 database | Existing foundation state survives and new tables exist |
| Restore | Dump an installed 0.2.0 database and restore into a clean database with different role and relation OIDs | Durable definitions, source identities, names, and artifacts load; explicit rebind restores their meaning |
| Security | Call constructors and actions through hostile `search_path` objects | Fixed-path functions use extension objects only |

Run the v0.1 commands plus:

```text
just test-definitions
just test-upgrade from=0.1.0
```

## Exit criteria

- [ ] All five noun constructors reject invalid local input and return canonical JSONB for valid input.
- [ ] `mdm.create()` stores exactly one immutable row for a changed definition.
- [ ] A submission equal to the current desired definition is a no-op; A→B→A creates valid history.
- [ ] `expected_version` prevents concurrent overwrite and leaves no partial state.
- [ ] Every supported and rejected source-key shape has an end-to-end test.
- [ ] `mdm.describe(..., 'definition')` round-trips into the same definition and artifact digests.
- [ ] The graph specification contains `EXTERNAL` and `initialize = false`, but no graph object exists in PostgreSQL.
- [ ] Disabled Graph V1 is visible in `describe` and does not block definition storage.
- [ ] The 0.1.0 to 0.2.0 extension upgrade passes.
- [ ] The first clean-database logical restore passes after explicit portable-name rebinding.
- [ ] Output names and reserved columns cannot collide or be truncated.
- [ ] Unauthorized execution-role nomination, row-security bypass, and post-definition privilege revocation fail closed.
- [ ] Direct helper calls and same-name role replacement cannot bypass authorization.
- [ ] Existing definitions cannot acquire unrecorded semantics through a newer artifact.
- [ ] The full v0.1 test matrix still passes.

After this release, revise the estimates for v0.3 through v0.7 from measured implementation and review time.

## Deferred

Do not execute graph SQL, allocate source-record IDs, normalize values, enumerate candidates, resolve pairs, or create public output tables. Those changes belong to later releases.
