# v0.3 implementation plan: normalization

## Outcome

Implement the first versioned cleaners, all seven normalized-value states, canonical binary ordering, and durable source-record identity. Make the normalization functions usable in future `pg_trickle` defining queries, but continue to test them without creating a live private graph.

## Prerequisites and dependency changes

Start from v0.2 with the source relations, logical types, cleaner names, options, and source-key expressions already validated in the graph specification.

Add one runtime crate and pin its exact artifact before implementation:

```toml
unicode-normalization = "=0.1.25"
```

Rust and PostgreSQL do not provide Unicode normalization in their standard libraries. Pin `unicode-normalization` 0.1.25 with crate checksum `5fd4f6878c9cb28d874b009da9e8d183b5abc80117c40bbd187a1fde336be6e8`; it embeds Unicode 17.0.0 data. Record that identity, the exact Rust toolchain and target, Cargo lockfile digest, PostgreSQL build, database encoding, collation provider and version, and fixture digest in the reproducibility manifest. Commit normalization and case-mapping vectors that change across supported Unicode versions. A dependency upgrade adds a cleaner version; it does not change an existing one. Do not add regular-expression, email, phone, or locale libraries. The V1 cleaners use bounded character scans and explicit rules.

Keep `pg_trickle` pinned. Use its public `pgtrickle.encode_row_id_v2(text, anyelement)` function for source-key encoding. Do not copy its encoder or read its row-identity inventory tables.

Add `sql/pg_mdm--0.2.0--0.3.0.sql`, archive the 0.3.0 install SQL, and extend the upgrade matrix to both supported starting versions.

## Schema skeleton

Add one composite type and one durable table:

```sql
CREATE TYPE mdm_internal.normalized_value AS (
    state text,
    normalized text,
    canonical_bytes bytea
);

CREATE TABLE mdm_internal.source_records (
    entity_id uuid NOT NULL REFERENCES mdm_internal.entities(entity_id),
    source_identity_id uuid NOT NULL
        REFERENCES mdm_internal.source_identities(source_identity_id),
    source_record_key bytea NOT NULL,
    source_record_id uuid NOT NULL DEFAULT uuidv7(),
    active boolean NOT NULL DEFAULT false,
    first_seen_at timestamptz NOT NULL DEFAULT statement_timestamp(),
    last_seen_at timestamptz NOT NULL DEFAULT statement_timestamp(),
    PRIMARY KEY (entity_id, source_identity_id, source_record_key),
    UNIQUE (source_record_id),
    UNIQUE (entity_id, source_record_id)
);
```

The durable identity is `(entity_id, source_identity_id, source_record_key)`. The UUID is an opaque handle. Never use UUID allocation order for semantic ordering. Register `source_records` with `pg_catalog.pg_extension_config_dump()`.

Rows created by v0.3 tests remain inactive. Live source observation and activation start only after graph integration and refresh. The table exists now so identity allocation and reactivation semantics can be proven before publication code depends on them.

Generate source keys in the future record-stage SQL with this shape:

```sql
pgtrickle.encode_row_id_v2(
    'MDM_SOURCE_KEY_V1',
    ROW(<entity ID>, <source identity ID>, <key column 1>, <key column 2>)
)
```

The number and types of key columns come from the validated definition. SQL identifiers use PostgreSQL quoting functions, not string concatenation.

## Cleaner contract

Return exactly one state for every input:

| State | Meaning | Can supply evidence? |
|---|---|---|
| `value` | The cleaner produced a valid normalized value | Yes |
| `absent` | The source value is SQL `NULL` | No |
| `empty` | A present value becomes empty after trimming | No |
| `invalid` | The value violates the cleaner's syntax or bounds | No |
| `unknown` | The source contract marks the value as unknown | No |
| `redacted` | The source contract marks the value as unavailable by policy | No |
| `unsupported` | The logical type or cleaner version cannot process the value | No |

Only `value` has `normalized` and `canonical_bytes`. All other states set both fields to null. The record-stage SQL reads the validated v0.2 state column. It passes only `present`, `unknown`, or `redacted`; cleaners do not infer states from magic strings. A redacted input value is never copied into normalized rows, diagnostics, provenance, logs, or dumps.

Freeze these V1 cleaners with fixture vectors before implementation:

| Cleaner | Input | V1 behavior |
|---|---|---|
| `text` | `text` | NFKC, Unicode lowercase, trim, and collapse whitespace |
| `person_name` | `text` | `text`, then map ASCII punctuation to spaces and collapse again |
| `company_name` | `text` | Same as `person_name`; do not remove legal suffixes |
| `email` | `text` | NFKC and trim; reject control or whitespace characters and anything other than one nonempty local part and domain; lowercase both parts |
| `phone` | `text` | Apply NFKC, allow one leading `+`, retain ASCII digits, discard common visual separators, and require 7 through 15 digits; reject other characters and do not infer a country code |
| `tax_id` | `text` | NFKC, uppercase, retain ASCII letters and digits, discard spaces and `-`; reject other characters and an empty result |
| `date` | PostgreSQL `date` | ISO `YYYY-MM-DD` |

Cleaner options may tighten bounds. They may not change locale or make results depend on the session. Reject unknown options.

Construct `canonical_bytes` as a version byte, a logical-type tag, and the normalized UTF-8 bytes. Compare it bytewise. Include the encoding version in the semantic manifest and fixture file. Do not use collation-sensitive ordering.

## API skeleton

Add internal SQL functions for future graph queries:

```sql
mdm_internal.normalize_text(
    value text,
    cleaner text,
    cleaner_version integer,
    source_state text DEFAULT 'present',
    options jsonb DEFAULT '{}'::jsonb
) RETURNS mdm_internal.normalized_value
IMMUTABLE PARALLEL SAFE
SET search_path = pg_catalog, mdm_internal, pg_temp

mdm_internal.normalize_date(
    value date,
    cleaner text DEFAULT 'date',
    cleaner_version integer DEFAULT 1,
    source_state text DEFAULT 'present',
    options jsonb DEFAULT '{}'::jsonb
) RETURNS mdm_internal.normalized_value
IMMUTABLE PARALLEL SAFE
SET search_path = pg_catalog, mdm_internal, pg_temp
```

The functions are not `STRICT` because SQL null must become `absent`. Dispatch by the exact `(logical type, cleaner name, cleaner version)` tuple recorded in the definition and artifact. Reject an unknown or unavailable version; never select a current or latest implementation. Revoke `EXECUTE` from `PUBLIC`; generated private graph queries run them under the bound execution role through explicit grants made during graph creation.

Keep source identity behind internal Rust functions:

```rust
pub(crate) fn source_key_sql(source: &ValidatedSource) -> Result<String, MdmError>;

pub(crate) fn get_or_create_source_record(
	entity_id: pgrx::Uuid,
	source_identity_id: pgrx::Uuid,
	source_record_key: &[u8],
) -> Result<pgrx::Uuid, MdmError>;
```

Under the `pg_test` feature, expose a `mdm_internal.test_get_or_create_source_record(...)` SQL wrapper for concurrency and reactivation tests. Omit that wrapper from release packages.

Use `INSERT ... ON CONFLICT ... DO UPDATE ... RETURNING source_record_id` so concurrent observation of one key returns one UUID. Reactivation reuses that UUID.

There is no new public action in v0.3. Extend `mdm.describe()` with the selected cleaner names, versions, options, and source-key encoding version.

## Implementation order

1. Write the normalization fixture format and canonical-byte vectors.
2. Implement `NormalizedState`, `NormalizedValue`, and byte ordering.
3. Implement the cleaners one file at a time against the shared fixture.
4. Add the internal SQL wrappers with fixed search paths and revokes.
5. Compile record and normalization stages into a new immutable artifact attachment.
6. Add `source_records` and its atomic get-or-create function.
7. Execute generated record and normalization SQL against ordinary fixture tables through the production terminal reader.
8. Extend `describe`, migrations, logical restore, upgrade tests, and API documentation.

Limit cleaner input length before allocating normalized output. Put the limit in the expanded definition and definition digest. A value over the limit returns `invalid`; it never truncates.

## Test matrix

| Level | Case | Expected result |
|---|---|---|
| Unit | Every fixture input and cleaner | State, normalized text, and canonical bytes match the committed vector |
| Unit | Null, whitespace-only, malformed, and over-limit values | `absent`, `empty`, or `invalid` as specified; no evidence bytes |
| Unit | Explicit unknown and redacted source states | The state survives without inspecting the display text |
| Unit | Two cleaner versions installed together | Each artifact dispatches the exact recorded version; an unknown version fails closed |
| Unit | Canonically equivalent Unicode forms | They produce equal normalized text and bytes |
| Unit | Different normalized values | Binary ordering is stable under locale changes |
| Unit | Email with missing or repeated `@`, controls, or spaces | `invalid` |
| Unit | Phone with separators, Unicode digits, missing country prefix, and invalid length | Deterministic result; no country inference |
| Unit | Company legal suffixes | Suffixes remain in the normalized value |
| Unit | Unknown cleaner, version, or option | `unsupported` or a definition error as specified |
| End to end | Scalar and composite source keys | `encode_row_id_v2` produces stable keys across rebuilds |
| End to end | Two sessions observe the same new source key | Both receive one `source_record_id` |
| End to end | Delete and reactivate one source key | The original `source_record_id` is reused |
| End to end | Change database collation and session locale settings | Normalized bytes and sort order remain unchanged |
| End to end | Call internal normalizers without a grant | PostgreSQL denies access |
| End to end | Execute generated record and normalization SQL with fixture source tables | Versioned terminal rows match the independently committed vectors |
| Security | Run generated SQL with hostile `search_path`, row-level security, then revoked source access | Qualified execution sees only allowed rows and revocation fails before derived writes |
| Security | Raise an error from generated SQL | The caller's role, search path, and configuration context remain unchanged |
| Restore | Restore v0.3 durable state into a clean database and rebind sources | Source-record IDs and frozen source identities survive while relation OIDs change |
| Upgrade | Upgrade 0.1.0 and 0.2.0 databases to 0.3.0 | Existing definitions and definition digests remain unchanged; new artifacts attach without rewriting them |

## Exit criteria

- [ ] The committed fixture covers every cleaner, state, supported option, boundary, and invalid class.
- [ ] All cleaners are immutable, bounded, locale-independent, and deterministic across clean builds.
- [ ] Only the `value` state can produce candidate or matching input.
- [ ] Canonical bytes define a total binary order and match their fixture vectors.
- [ ] Scalar and supported composite source keys use `pgtrickle.encode_row_id_v2` and remain stable across rebuilds.
- [ ] Concurrent insertion and reactivation preserve one durable `source_record_id`.
- [ ] The generated graph specification contains executable record and normalization stages, but no live graph exists.
- [ ] PostgreSQL executes those stages against fixture sources and the production reader returns the committed terminal rows.
- [ ] `mdm.describe()` reports cleaner and row-identity versions.
- [ ] The reproducibility manifest pins the exact crate, Unicode data, toolchain, PostgreSQL, collation, lockfile, artifact, and fixture identities.
- [ ] Clean logical restore preserves source-record identity after explicit source rebinding.
- [ ] Upgrade tests from every prior release and the complete v0.1 through v0.2 matrices pass.

## Deferred

Do not add address parsing, country inference, legal-suffix dictionaries, transliteration, custom functions, locale-specific rules, or lookup tables. Add a cleaner only with a versioned contract and fixture vectors.
