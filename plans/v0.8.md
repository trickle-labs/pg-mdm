# v0.8 implementation plan: pg_trickle graph integration

## Outcome

Turn one immutable compiled artifact into a private, transactionally installed
`pg_trickle` Graph V1 graph. Keep every member in `EXTERNAL` orchestration with
initialization disabled. Store the public member and graph contracts in one
append-only, database-local graph binding.

Extend `mdm.create()` to install or reuse that exact binding. Extend
`mdm.describe()` to report it. Do not refresh the graph, resolve records, or
activate the desired definition in this release; those operations start in
v0.9.

## Start gate

v0.8 uses the released `pg_trickle` artifact containing the source delegation
behavior described in upstream commit
[`e995812`](https://github.com/trickle-labs/pg-trickle/commit/e99581268c99697bba02db50726390a48f538585)
and admitted by the pg-mdm suite. The exact release is pinned in
`DEPENDENCIES.md`; do not pin an upstream branch or locally built archive in
release or CI configuration.

The pinned release is `pg_trickle` v0.105.1 with its tagged, checksummed
package.

The qualifying release must preserve these rules:

- Graph members require owner-equivalent authority.
- A base-table source requires owner-equivalent authority or schema `USAGE`
  plus table `SELECT` and `MAINTAIN`.
- Revoking `SELECT`, `MAINTAIN`, or required schema access makes contract and
  strict-refresh calls fail closed.
- Contract inspection and graph refresh preserve the selected execution role
  and its row-level-security view.

pg-mdm validates these grants but never grants them on a user's source table.
The source owner remains the authority that delegates coordination.

The admission record is:

1. Pin its exact version, release commit, tag object, package URL, and SHA-256.
2. Change the admission fixture so the execution role does not own the source.
3. Grant that role schema `USAGE` and table `SELECT, MAINTAIN`.
4. Prove successful contract and strict-refresh calls, then prove that each
   revocation blocks the same calls before graph mutation.
5. Re-run the complete pg-mdm install, upgrade, restore, security, and E2E
   suites against the packaged artifact.

## Release boundary

v0.8 adds live graph installation and inspection only.

It includes:

- one new executable compiler artifact attached to each eligible definition;
- private physical-name allocation and logical-to-physical stage rendering;
- transactional stream-table creation through public Graph V1 SQL;
- member-contract and graph-contract validation;
- append-only graph bindings and member bindings;
- idempotent retry and complete rollback on failure;
- graph state in `mdm.describe()`; and
- explicit entity cleanup through public `pg_trickle` lifecycle functions.

It excludes `mdm.preview()`, `mdm.refresh()`, `mdm_admin.rebuild()`, graph
activation, source-frontier consumption, terminal-relation reads, MDM
publication, Delta V1, and retirement of an older active graph. Those changes
belong to v0.9 or later.

## Executable artifact

The v0.7 compiler emitted development artifact format 1, compiler version 4.
Those artifacts remain immutable and non-executable.

Add compiler version 5 as a new append-only attachment to an existing
definition when every semantic input required by the stored definition is
present. Version 5 must:

- emit executable SQL for every record, normalization, block-statistics,
  overflow, pair, evidence, and golden-candidate stage;
- preserve the versioned cleaners, comparators, candidate predicates, hard
  limits, and terminal schemas already stored with the definition;
- keep `initialize = false` and `orchestration_mode = EXTERNAL` on every node;
- expose all logical dependencies explicitly and reject cycles, missing nodes,
  duplicate logical IDs, and missing roots before DDL; and
- remain portable by excluding database OIDs and generated relation names from
  the artifact bytes and artifact digest.

Installation maps logical IDs to private relation names and renders only exact
compiler-issued relation references. The rendered query and public
`pg_trickle` contract become part of the graph binding, not the portable
artifact.

## Private graph objects

Add an extension-owned `mdm_graph` schema. Revoke all access from `PUBLIC`.
The configured helper owner owns the schema. An installation helper grants the
bound execution role `USAGE` and transaction-local `CREATE`; the invoker calls
`pgtrickle.create_stream_table()` as that role; the helper revokes `CREATE`
before the statement commits. Keep `USAGE` so the role can inspect and refresh
its owned members later.

Generate each member name from the binding UUID and its topological ordinal.
The complete name must fit PostgreSQL's 63-byte identifier limit without
truncation. Never reuse an existing name or adopt a relation that was not
created by the current installation transaction.

Create members in topological order with:

```text
initialize = false
orchestration_mode = EXTERNAL
cdc_mode = trigger
refresh_mode = AUTO
```

Call only these public upstream APIs:

```text
pgtrickle.integration_capabilities()
pgtrickle.create_stream_table(...)
pgtrickle.stream_table_contract(regclass)
pgtrickle.graph_contract(regclass[])
pgtrickle.drop_stream_table(text, boolean)
```

Do not read `pgtrickle` catalogs, generated columns, change buffers, frontiers,
or scheduler state.

## Graph binding

Add derived extension tables with this minimum shape:

```sql
CREATE TABLE mdm_internal.graph_bindings (
    graph_binding_id uuid PRIMARY KEY DEFAULT pg_catalog.uuidv7(),
    entity_id uuid NOT NULL REFERENCES mdm_internal.entities(entity_id),
    definition_version bigint NOT NULL,
    artifact_id uuid NOT NULL
        REFERENCES mdm_internal.definition_artifacts(artifact_id),
    graph_generation bigint NOT NULL CHECK (graph_generation > 0),
    execution_role_oid oid NOT NULL,
    source_binding_digest bytea NOT NULL
        CHECK (octet_length(source_binding_digest) = 32),
    root_relation_oids oid[] NOT NULL,
    graph_contract_version smallint NOT NULL CHECK (graph_contract_version = 1),
    graph_digest bytea NOT NULL CHECK (octet_length(graph_digest) = 32),
    graph_contract jsonb NOT NULL,
    graph_binding_digest bytea NOT NULL
        CHECK (octet_length(graph_binding_digest) = 32),
    created_at timestamptz NOT NULL DEFAULT pg_catalog.statement_timestamp(),
    UNIQUE (entity_id, graph_generation),
    FOREIGN KEY (entity_id, definition_version)
        REFERENCES mdm_internal.definitions(entity_id, definition_version)
);

CREATE TABLE mdm_internal.graph_members (
    graph_binding_id uuid NOT NULL
        REFERENCES mdm_internal.graph_bindings(graph_binding_id),
    logical_id text NOT NULL,
    topological_ordinal integer NOT NULL CHECK (topological_ordinal >= 0),
    relation_oid oid NOT NULL,
    relation_name text NOT NULL,
    contract_generation bigint NOT NULL CHECK (contract_generation > 0),
    contract_digest bytea NOT NULL CHECK (octet_length(contract_digest) = 32),
    contract jsonb NOT NULL,
    PRIMARY KEY (graph_binding_id, logical_id),
    UNIQUE (graph_binding_id, topological_ordinal),
    UNIQUE (relation_oid)
);
```

These rows contain database-local OIDs and physical names. Preserve them across
extension upgrades, but do not register their contents with
`pg_extension_config_dump()`. A clean logical restore rebuilds them after role
and source rebinding. Later durable publication rows retain the binding digest
as evidence without a foreign key to this derived registry.

`graph_binding_digest` hashes the domain tag `pg_mdm/graph-binding/v1`, artifact
digest, graph generation, execution-role binding, sorted source bindings,
sorted logical-to-physical member identities and contracts, sorted roots, and
the canonical Graph V1 digest. Add fixed canonical fixture vectors.

## Transactional installation

Run installation inside the outer `mdm.create()` statement:

1. Require enabled `external_graph_refresh` major 1.
2. Verify the selected role binding, source identities, current source OIDs,
   schema `USAGE`, table `SELECT, MAINTAIN`, RLS contract, and executable
   artifact digest.
3. Lock the entity row and allocate the next graph generation and binding UUID.
4. Open transaction-local `CREATE` access to `mdm_graph`.
5. Create every member in topological order as the selected execution role.
6. Read and validate each public stream-table contract immediately. Require
   contract version 1, exact owner, `EXTERNAL` mode, expected defining-query
   identity, output schema, dependencies, row-identity version, and source
   identity.
7. Read `graph_contract()` for the complete root closure. Require contract
   version 1, the exact member and source sets, exact roots, acyclic topological
   order, and no unrecognized contract fields that change required meaning.
8. Compute and insert the immutable graph binding and member rows.
9. Revoke schema `CREATE`, then recheck every physical OID, owner, contract
   generation, contract digest, graph digest, role binding, and source binding.
10. Mark the create operation successful and return. Do not set
    `entities.active_version`.

An exact valid binding makes an idempotent retry a no-op. A name collision,
unsupported stage, contract mismatch, ownership mismatch, changed source,
revoked grant, or injected error aborts the statement. PostgreSQL rolls back
all stream tables, schema grants, registry rows, definition changes, and the
operation record together.

## Authorization and lifecycle

Public source and graph work remains `SECURITY INVOKER`. Require `current_user`
to equal the stored execution-role name and OID. Reject superuser,
`BYPASSRLS`, extension-owner, same-name replacement, or inherited ownership
that bypasses the stored RLS contract.

Internal helpers may allocate names, change `mdm_graph` ACLs, and write the
registry. They must independently verify their caller and inputs, use the fixed
helper search path, and never query source rows, call Graph V1, or change role.

Add `mdm_admin.drop_entity(entity_name text, confirm text)` now that entities
own physical graphs. Require the selected execution role, an explicit
confirmation equal to the entity name, and the administrator function grant.
Validate every stored OID and owner, drop graph members in reverse topological
order through `pgtrickle.drop_stream_table()`, then remove public outputs and
durable entity state in the same transaction. Any mismatch or failure rolls
back the complete drop. Entity rename remains unsupported.

## Describe and errors

For authorized callers, add these fields to `mdm.describe(..., 'summary')`:

```text
graph_state: absent | ready | blocked
graph_generation
graph_binding_digest
graph_contract_version
graph_digest
member_count
root_count
blocking_errors
```

Do not expose generated SQL, physical relation names, raw source bindings, or
contract payloads in the ordinary summary. A missing qualifying upstream
release, missing executable artifact, changed role or source binding, revoked
grant, missing member, contract drift, or graph-digest drift reports one stable
blocking error and prevents reuse.

Add stable codes for graph artifact, installation, contract, binding, and
lifecycle failures. Preserve upstream Graph V1 identifiers in protected detail
when available, but return an MDM code at the public boundary.

## Implementation order

Treat each step as a separate review gate.

### v0.8a: dependency admission

1. Admit a released upstream artifact containing source delegation.
2. Replace source ownership in the admission fixture with `SELECT, MAINTAIN`
   delegation and preserve non-owner RLS behavior.
3. Pass grant, revocation, rollback, capability, and forbidden-private-access
   cases.
4. Interleave committed source writes with a rollback-only strict refresh. Prove
   that each source change is either in the returned boundary or remains
   pending for the next refresh. Retry after rollback must not skip or duplicate
   a source change.

### v0.8b: executable artifact

1. Complete compiler version 5 without changing older artifact bytes.
2. Add canonical artifact vectors and executable SQL fixture checks.
3. Compare every terminal relation with the existing v0.3 through v0.7
   production-shaped fixtures before installing a live graph.

### v0.8c: graph installation

1. Add the private schema, derived registry, digest encoder, and physical-name
   allocator.
2. Install members transactionally through public Graph V1 calls.
3. Validate member and graph contracts and expose bounded summary state.

### v0.8d: lifecycle and recovery boundary

1. Add confirmed entity drop through public upstream lifecycle calls.
2. Add the 0.7.0 to 0.8.0 migration, archive, helper-owner procedure, upgrade
   tests, and clean-restore rebuild boundary.
3. Run the full admission, security, upgrade, restore, and package suites.

## Test matrix

| Level | Case | Expected result |
|---|---|---|
| Unit | Compile the same stored definition repeatedly | Version 5 artifact bytes and digest stay equal |
| Unit | Shuffle graph nodes or dependencies | Topological order, rendered graph, and binding digest stay equal |
| Unit | Change a physical name, role OID, source OID, member contract, root, or graph digest | Only the graph-binding digest changes |
| Unit | Duplicate, missing, cyclic, placeholder, or non-executable node | Installation is rejected before DDL |
| End to end | Install a multi-source, multi-stage definition | Every member is execution-role-owned, uninitialized, and `EXTERNAL` |
| End to end | Re-submit an unchanged definition | The exact valid binding is reused without new members |
| End to end | Update A→B→A | Each definition and artifact stays immutable; each installed generation has its own names and binding |
| End to end | Inject failure after each member and registry write | No member, grant, binding, definition update, or successful operation remains |
| Conformance | Source owner grants schema `USAGE` and table `SELECT, MAINTAIN` | A non-owner execution role can inspect the contract and perform a rollback-only strict refresh |
| Conformance | Revoke `SELECT`, `MAINTAIN`, or schema `USAGE` | Contract and strict refresh fail before graph mutation |
| Conformance | Interleave committed source writes with a rollback-only strict refresh | Every source change is either in the returned boundary or pending for the next refresh; retry causes no loss or duplication |
| Security | Change policy, policy dependency, role membership, or session-dependent RLS input without source DML | The graph invalidates or the definition is rejected; stale evidence is never accepted |
| Security | Use a hostile `search_path` and colliding objects | Only schema-qualified extension and bound objects are used |
| Security | Call each helper directly with forged entity, role, artifact, name, or contract data | No grant, graph object, or registry row changes |
| Security | Concurrent installations use the private schema | ACL serialization cannot lend one role another role's create window or objects |
| Lifecycle | Confirmed drop with an exact binding | Members, outputs, and entity state disappear atomically |
| Lifecycle | Drop with wrong confirmation, changed OID, changed owner, or upstream failure | Nothing is removed |
| Upgrade | Upgrade an installed 0.7.0 database | Durable state survives and no graph is invented |
| Restore | Restore durable state with new role and relation OIDs | Graph state is blocked until explicit rebind and a new installation |
| Encapsulation | Trace SQL and scan source | No pg_trickle private catalog or internal function is referenced |

## Exit criteria

- [ ] A released, checksummed `pg_trickle` artifact with delegated-source
      authorization passes the complete admission suite.
- [ ] Every eligible definition has an immutable executable compiler-version-5
      artifact; older artifacts are byte-for-byte unchanged.
- [ ] `mdm.create()` installs or reuses one exact private Graph V1 binding
      without activating or refreshing it.
- [ ] Every member is owned by the bound execution role, starts empty, remains
      `EXTERNAL`, and is absent from ordinary pg_trickle scheduler work.
- [ ] Member and graph contracts match the stored artifact, sources, role,
      roots, and graph-binding digest.
- [ ] Source delegation, revocation, owner changes, RLS changes, role
      replacement, and contract drift fail closed before graph mutation.
- [ ] Every injected failure and concurrent installer case leaves no partial
      graph, transient schema grant, registry row, or definition update.
- [ ] `mdm.describe()` reports bounded graph state without disclosing private
      SQL or physical names.
- [ ] Confirmed entity drop is transactional and uses only public pg_trickle
      lifecycle functions.
- [ ] The 0.7.0 to 0.8.0 upgrade, clean logical restore boundary, package
      manifest, and all earlier release tests pass.
- [ ] No graph refresh, frontier consumption, MDM resolution, publication, or
      Delta V1 dependency is introduced.

## Deferred

v0.9 adds strict graph refresh, complete terminal reads, full resolution, and
atomic publication. v0.10 hardens concurrency, crash recovery, clone, backup,
restore, upgrade, and full-fallback behavior. v0.11 runs release qualification.
