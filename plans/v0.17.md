# v0.17 implementation plan: explicit merge and split stewardship

## Outcome

Add authenticated merge and complete split directives over durable source-record
subjects. Each write accepts an exact action preview, appends bounded immutable
constraints, increments the decision epoch once, and publishes only through the
normal refresh path.

Keep the V1 clustering and stable-ID policies. This release does not add
move-member, locks, bulk actions, approval voting, or automation authority for
merge and split.

## Start gate

Require v0.16 exact preview parity, manifest freshness checks, preview retention,
and resource failures. A definition-level preview alone cannot authorize an
identity action. Add action-specific preview before either write API.

## Action preview

Extend `mdm.preview()` with `merge` and `split` modes. Both return
`evidence_level = exact_subjects`, an action preview digest, the complete affected
closure and constraint counts and digests, plus bounded constraint detail,
continuity, memberships, golden and review changes, contradictions, reasons, and
expiry. The digest covers the complete result even when returned detail is
truncated.

`merge` options contain only:

```json
{"mdm_ids":["uuid", "uuid"]}
```

Require at least two distinct active canonical IDs at the current base publication.
Resolve them immediately to the complete active member set. Store only durable
source-record IDs as directive subjects. Input entity IDs remain lookup handles.

`split` options contain only:

```json
{"mdm_id":"uuid","partitions":[["source-record-uuid"],["source-record-uuid"]]}
```

Require one active canonical ID and at least two non-empty partitions. Every
active member at the base revision must appear exactly once. Reject foreign,
inactive, duplicate, missing, or extra records. A partial partition is never a
request to let the resolver decide the rest.

Expand active manual decisions and entity directives to the complete affected
constraint closure. Stop at `max_decision_closure`. A limit failure returns no
preview digest.

## Constraint compilation

Compile a merge into `MATCH` for every unordered pair of named active members.
Compile a split into `MATCH` for every pair within a partition and `NOT_MATCH` for
every pair in different partitions. Canonically order endpoints by source-record
key and then UUID. Deduplicate identical constraints and reject conflicting ones.

The complete pair expansion is deliberate. It preserves the action when an
anchor becomes dormant and later reactivates. Enforce the existing decision
closure limit before building the full set. Do not introduce a second lock or
partition primitive into the resolver in this release.

Run the compiled set through the existing manual-constraint contradiction checks
and full resolver. Reuse the v0.16 `Evaluation` path for impact. The continuity
plan records the V1 survivor and split-child ID choice. New split children use
preview-local handles until refresh allocates durable UUIDs.

## Directive ledger

Add logged `mdm_internal.entity_directives`:

```text
directive_id               uuid primary key
entity_id                  uuid not null
directive_kind             text not null: MERGE | SPLIT
directive_version          bigint not null, positive
request_key                bytea not null, 32 bytes
request_digest             bytea not null, 32 bytes
base_publication_revision  bigint not null
base_decision_epoch        bigint not null
decision_epoch             bigint not null
preview_id                 uuid not null
preview_digest             bytea not null, 32 bytes
subjects                   jsonb not null
continuity_plan            jsonb not null
constraint_digest          bytea not null, 32 bytes
reason                     text not null
created_by_name            text not null
created_as_role_name       text not null
operation_id               uuid not null
created_at                 timestamptz not null
is_current                 boolean not null
```

Enforce `(entity_id, request_key)` uniqueness. An identical authenticated retry
returns the existing directive. Different request bytes return
`MDM_IDEMPOTENCY_CONFLICT`.

Store compiled rows in `mdm_internal.entity_directive_constraints` with directive
ID, ordinal, canonical endpoints, and `MATCH` or `NOT_MATCH`. Add indexes for both
endpoints. The constraint digest covers the complete ordered set.

Add `mdm_internal.entity_directive_supersessions` and
`mdm_internal.directive_decision_supersessions`. A new directive names every old
entity directive and pair decision that it intends to replace. Update old rows to
non-current and append links in the same transaction. A timestamp alone never
wins a contradiction.

Extend both deferred chain validators so a current row becomes non-current only
when the matching supersession link exists. A directive may supersede a pair
decision only when its compiled constraint has the same canonical endpoints.

Load current directive constraints beside current `steward_decisions` in
`load_decisions()`. Keep inactive-record constraints dormant rather than deleting
them. They become active again when both records reactivate.

## Write APIs

Install these public functions:

```text
mdm_steward.merge_entities(
    entity_name text,
    mdm_ids uuid[],
    expected_publication_revision bigint,
    expected_decision_epoch bigint,
    preview_digest bytea,
    request_key bytea,
    supersede_directive_ids uuid[],
    supersede_decision_ids uuid[],
    reason text
) -> operation_id uuid, directive_id uuid, directive_version bigint,
     decision_epoch bigint

mdm_steward.split_entity(
    entity_name text,
    mdm_id uuid,
    partitions jsonb,
    expected_publication_revision bigint,
    expected_decision_epoch bigint,
    preview_digest bytea,
    request_key bytea,
    supersede_directive_ids uuid[],
    supersede_decision_ids uuid[],
    reason text
) -> operation_id uuid, directive_id uuid, directive_version bigint,
     decision_epoch bigint
```

Require the entity execution role and the same helper-owner protections as
`mdm_steward.decide()`. Explicitly revoke both functions from `PUBLIC` and from
every policy automation role.

Under the entity row lock:

1. Authenticate before looking up a prior request.
2. Return an identical prior directive or reject a changed request body.
3. Require the expected publication and decision epoch to equal current values.
4. Load the unexpired action preview and compare its digest, action bytes,
   definition, artifact, graph, source boundary, role, base identity digest, and
   decision epoch with current state.
5. Recompute the complete constraint closure and require the stored preview
   constraint and result digests to match.
6. Validate every explicit supersession and contradiction.
7. Append the directive, constraints, supersession links, and operation record,
   then increment `entities.decision_epoch` once.

The write does not edit memberships, aliases, splits, goldens, reviews, or public
outputs. `mdm.describe()` reports pending stewardship until a successful refresh
observes the new epoch.

## Refresh and explanation

At refresh, combine active pair decisions and active directive constraints before
automatic edges. Preserve the existing precedence: structural integrity, then
manual constraints, then automatic component rules and evidence.

Revalidate active directive coherence before publication. If later active records,
manual decisions, or directives make the complete set contradictory, fail the
refresh and keep the prior publication. Never drop only the conflicting row.

Use the combined pair-decision and directive constraint set in `decide()` and in
both new write APIs. A later pair decision cannot bypass an active entity
directive. Every accepted merge or split marks open policy cases pending through
the v0.13 helper in the same transaction as the decision-epoch increment.

Record directive IDs and constraint ordinals in resolution facts. Extend
`mdm.explain()` with subject kind `directive` and bounded links from the request to
compiled constraints, accepted or rejected unions, continuity, golden changes,
reviews, and the resulting publication.

Do not add a general directive trait or separate resolver. Two action variants and
one canonical pair-constraint compiler cover the release.

## Upgrade and restore

Register directive rows, constraints, and supersession links for logical dump.
Extend `configure_helper.sql` with their owners and private ACLs. Extend
`mdm_admin.drop_entity()` to remove them in dependency order. A failed drop
preserves the ledger and public outputs.

## Implementation order

1. Freeze action encodings and exhaustive small partition fixtures.
2. Implement pure merge and split constraint compilation and reuse contradiction
   checks.
3. Add action preview and exact impact through `Evaluation`.
4. Add the directive ledger, child constraints, and explicit supersession links.
5. Add authenticated write APIs and idempotent request handling.
6. Load directives through normal refresh and extend bounded explanation.
7. Add the `0.16.0` to `0.17.0` migration, logical dump coverage, restore tests,
   archive, and documentation.

## Test matrix

| Case | Required result |
|---|---|
| Two-entity merge | All named members join; V1 survivor matches preview |
| Three-entity merge | Complete pair constraints and deterministic result |
| Complete split | Every member appears in one predicted child |
| Partial or duplicate split | Atomic rejection before ledger writes |
| Existing `NOT_MATCH` or `MATCH` conflict | Bounded contradiction unless explicitly superseded |
| Dormant member | Constraint persists and applies on reactivation |
| Stale publication, epoch, or preview | No directive or epoch change |
| Source, RLS, role, definition, or graph change | Preview rejected as stale |
| Concurrent writers | One locked order; stale writer fails |
| Identical retry | Same directive and one epoch increment |
| Changed request key body | Idempotency conflict |
| Refresh failure | Directive stays pending; public output remains complete |
| Later successful refresh | Membership, identity, provenance, and review equal preview |
| Restore | Ledger, supersessions, dormant constraints, and retry identity survive |
| Automation role | Both APIs remain denied |

Property-test small member sets by comparing the compiled constraints with an
independent partition oracle. One pair in the output must have exactly one
classification, and every active subset must retain the requested relation.

## Exit criteria

- [ ] Every merge and split accepts an exact, fresh, action-specific preview.
- [ ] Split partitions cover the complete current membership exactly once.
- [ ] Compiled constraints preserve the action through dormancy and reactivation.
- [ ] Contradictions require explicit supersession and fail atomically.
- [ ] Retry, concurrency, refresh failure, and restore preserve one immutable
  directive history.
- [ ] Normal refresh produces the previewed memberships, V1 ID continuity,
  provenance, and reviews.
- [ ] Policy automation roles have no merge, split, or pair-decision authority.
- [ ] Cumulative upgrade, security, package, and E2E checks pass.

## Deferred

Do not add move-member, identity or membership locks, alternate continuity,
bulk actions, approval requirements, or React-issued identity actions. Add one
only after a named workflow supplies its precedence and preview requirements.
