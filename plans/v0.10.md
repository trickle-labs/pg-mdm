# v0.10 implementation plan: operational hardening

## Boundary

Keep the v0.9 public API and Graph V1 integration. Make refresh fail closed
when database-local graph bindings drift or resolver limits would be exceeded.
Do not add Delta V1, private `pg_trickle` catalog access, or new MDM
semantics.

## Changes

- Bind refresh access to the selected entity's current graph generation.
- Verify every bound graph member's relation OID and owner before refresh.
- Apply `max_active_records` while loading source rows, before resolution.
- Add lookup indexes and the 0.9.0 to 0.10.0 upgrade path.
- Extend the cumulative E2E path through extension upgrade, limit failure and
  retry, backup/restore, and clone isolation.

## Exit evidence

- [x] Formatting, Clippy, unit, package/archive, security, and upgrade checks pass against the tagged v0.10 source/package.
- [x] The tagged v0.10 Docker E2E suite passes against PostgreSQL 18 and the pinned `pg_trickle` 0.105.1 package.
- [x] The tagged v0.10 E2E run preserves the concurrent-writer and restore/rebind checks.
