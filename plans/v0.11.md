# v0.11 implementation plan: release qualification

## Boundary

Keep the v0.10 SQL API and PostgreSQL behavior. Add release qualification for
the exact `pg_trickle` 0.105.1 package already pinned in `DEPENDENCIES.md` and
CI. Do not add a new upstream contract or MDM feature.

## Qualification suite

The tagged v0.11.0 run on `pg_trickle` 0.105.1 failed at the duplicate-email
merge check below. A fresh `rtk just test-e2e` run on 2026-09-13 passed from
the v0.12.0 sign-off commit with PostgreSQL 18 and `pg_trickle` 0.105.2; its
retained result is in [`evidence/v0.12/docker-e2e-envelope.json`](../evidence/v0.12/docker-e2e-envelope.json).
This later run closes the behavior checks marked below, but does not retroactively
qualify the v0.11.0 release against 0.105.1.

- [x] Refresh matching Graph V1 probe tables in `AUTO` and `FULL` modes together.
  Compare their rows at each returned source boundary after inserts, updates,
  deletes, and no-op refreshes. Require `AUTO` to report differential
  maintenance on the supported steady-state scan, and require `FULL` to report
  full maintenance. (The tagged v0.11 run passed these earlier assertions.)
- [x] Drive the compiled MDM graph through source inserts, updates, deletes, and
  no-op refreshes. Compare active memberships with the independent fixture
  expectations for duplicate-email merges and splits. (The current v0.12.0
  cumulative E2E passed these checks on 0.105.2; the tagged v0.11 run failed on
  0.105.1.)
- [x] Inject an output-write failure after Graph V1 maintenance. Check that the
  publication revision, history, and public entity, member, and review rows
  remain unchanged. Retry and require the source change to appear at a proven
  source boundary. (Passed in the current v0.12.0 cumulative E2E run.)
- [x] Commit a source write after graph maintenance has returned its boundary but
  before MDM publication. Require that write to remain pending until the next
  refresh. (Passed in the current v0.12.0 cumulative E2E run.)
- [x] Keep the cumulative capability, authorization, RLS, concurrency, resolver
  limit, upgrade, backup, restore, and clone checks in the same CI suite.
  (The current v0.12.0 cumulative E2E run passes these checks on 0.105.2.)

The paired Graph V1 fixtures use only public `pg_trickle` SQL. The MDM tests
read public outputs and do not inspect `pg_trickle` catalogs, change buffers,
or scheduler state.
