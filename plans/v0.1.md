# v0.1 implementation plan: extension foundation

## Outcome

Ship an installable extension that depends on `pg_trickle`, creates the five empty V1 namespace schemas, protects internal state, records successful operations, and reports the upstream integration capability state. Do not create entities or execute a private graph in this release.

Use the released `pg_trickle` v0.98.0 artifact as the deliberate foundation baseline. Pin commit `737927d336aabfff3b69bc2b0c29917b556c3626` (tag object `168faa71074a81ba4315bf3a162dc5c32cc914dd`). CI installs `pg_trickle-0.98.0-pg18-linux-amd64.tar.gz`, whose published SHA-256 is `6b8a9cd3bb4761ede6150c29ba01f27eecbc2e3cffd5a85096c5683809c17fa7`. Its tagged source confirms PostgreSQL 18, `pgrx` 0.18.0, trigger-only stable capture, and disabled `external_graph_refresh` 1.0 and `output_delta_consumer` 1.0 capabilities. `pg_trickle` v0.98.1 was also released on 9 September 2026 and still advertises both capabilities as disabled, so it does not remove the gate. Record the derived image digest, capability response, and remaining build provenance in the dependency lock before implementation starts. Do not build against a moving checkout or switch the baseline without a reviewed qualification change.

## Dependency setup

Inherit the v0.98.0 toolchain as one unit:

- Rust 2024 edition.
- PostgreSQL 18 only.
- `pgrx = "=0.18.0"` with a default `pg18` feature.
- Runtime crates: `serde`, `serde_json`, `sha2`, and `thiserror`.
- Test crates: `pgrx-tests`, `sqlx`, `testcontainers`, `testcontainers-modules`, and `tokio` at the versions already proven by `pg_trickle`.
- `just` as the command entry point. Keep commands as thin wrappers around Cargo and test scripts.

Start with these manifest entries:

```toml
[dependencies]
pgrx = "=0.18.0"
serde = { version = "1", features = ["derive"] }
serde_json = "1"
sha2 = "0.11"
thiserror = "2"

[dev-dependencies]
pgrx-tests = "=0.18.0"
sqlx = { version = "0.9", features = ["runtime-tokio", "postgres", "json"] }
testcontainers = "0.27"
testcontainers-modules = { version = "0.15", features = ["postgres"] }
tokio = { version = "1", features = ["rt-multi-thread", "macros"] }

[features]
default = ["pg18"]
pg18 = ["pgrx/pg18", "pgrx-tests/pg18"]
pg_test = []
```

Set `requires = 'pg_trickle'`, `relocatable = false`, `superuser = true`, and `trusted = false` in `pg_mdm.control`. `pg_mdm` does not register a background worker or add itself to `shared_preload_libraries`; the selected `pg_trickle` package retains that deployment requirement.

Build the end-to-end image from an immutable PostgreSQL 18 image with the pinned extension artifact installed. Configure `shared_preload_libraries = 'pg_trickle'`. Permit a local image override for development, but do not make the sibling source checkout a Cargo or package dependency.

The dependency lock is one reproducibility record. It names the Rust toolchain, target, Cargo lockfile digest, PostgreSQL build and image digest, `pgrx` version, `pg_trickle` artifact, and every packaged extension file checksum.

Do not create cluster roles. PostgreSQL extensions do not own global roles reliably. Revoke default access, then document grants that administrators apply to their own configurator, steward, output-reader, explanation-reader, and administrator roles.

## Schema skeleton

Install only durable foundation objects:

```sql
CREATE SCHEMA mdm;
CREATE SCHEMA mdm_out;
CREATE SCHEMA mdm_steward;
CREATE SCHEMA mdm_admin;
CREATE SCHEMA mdm_internal;

CREATE TABLE mdm_internal.operations (
    operation_id uuid PRIMARY KEY DEFAULT uuidv7(),
    operation_kind text NOT NULL,
    entity_name name,
    status text NOT NULL CHECK (status IN ('running', 'succeeded', 'failed')),
    result_code text,
    outcome jsonb NOT NULL DEFAULT '{}'::jsonb,
    actor_name text NOT NULL,
    started_at timestamptz NOT NULL DEFAULT statement_timestamp(),
    completed_at timestamptz,
    CHECK ((status = 'running') = (completed_at IS NULL))
);

SELECT pg_catalog.pg_extension_config_dump(
    'mdm_internal.operations'::pg_catalog.regclass,
    ''
);

REVOKE ALL ON SCHEMA mdm_internal FROM PUBLIC;
REVOKE ALL ON ALL TABLES IN SCHEMA mdm_internal FROM PUBLIC;
REVOKE CREATE ON SCHEMA mdm, mdm_out, mdm_steward, mdm_admin FROM PUBLIC;
```

The operation table stores committed work. A failed transaction cannot preserve its own failure row. An external scheduler may record a failed attempt in a new transaction, but no semantic rule depends on that row.

Classify every table as durable or derived in the migration that introduces it. Register every durable extension-member table with `pg_catalog.pg_extension_config_dump()`. Keep the configuration-table foreign-key graph acyclic so a clean logical restore does not require disabled constraints or manual row ordering. Derived relations and database-local bindings are rebuilt and are not registered. Physical recovery and logical dump and restore are separate test paths.

Use `name` only for PostgreSQL identifiers. Store result codes as text so new codes do not require an enum migration. Validate codes in Rust and document them before they become public.

## API skeleton

Keep capability discovery behind one internal Rust adapter:

```rust
pub(crate) struct Capability {
	pub major: i16,
	pub minor: i16,
	pub enabled: bool,
	pub details: serde_json::Value,
}

pub(crate) struct PgTrickleCapabilities {
	pub external_graph_refresh: Capability,
	pub output_delta_consumer: Capability,
}

pub(crate) fn integration_capabilities() -> Result<PgTrickleCapabilities, MdmError>;
pub(crate) fn require_graph_v1() -> Result<Capability, MdmError>;
```

The adapter may call only:

```sql
SELECT capability, major_version, minor_version, enabled, details
FROM pgtrickle.integration_capabilities();
```

Treat the following states differently:

- Graph V1 1.x present and disabled: supported installation, blocked graph execution.
- Graph V1 absent: `MDM_PGT_CAPABILITY_MISSING`.
- Graph V1 has another major: `MDM_PGT_CAPABILITY_VERSION`.
- Duplicate capability rows or malformed details: `MDM_PGT_CAPABILITY_INVALID`.
- Delta V1 absent or disabled: accepted because V1 does not consume output deltas.

Do not call `stream_table_contract`, `graph_contract`, `set_orchestration_mode`, or `refresh_graph_strict` while Graph V1 is disabled. Do not read `pgtrickle` tables or generated columns.

Every `SECURITY DEFINER` function must use this fixed path, including functions that do not create temporary objects:

```sql
SET search_path = pg_catalog, mdm_internal, pg_temp
```

The temporary schema must remain last. Schema-qualify every relation, function, operator, and cast in security-definer SQL. Give each function a non-login least-privilege owner, revoke its default `PUBLIC` execution grant in the same transaction that creates it, and reject unqualified dynamic SQL in the static check.

Public source-facing actions added in v0.2 are `SECURITY INVOKER`. Narrow security-definer helpers may write protected catalogs but never query source data or change role. PostgreSQL does not permit `SET ROLE` inside a security-definer function. Tests must keep the authenticated `session_user`, a caller-selected `current_user`, and the function owner distinct.

## Implementation order

1. Create the crate, control file, `justfile`, and PostgreSQL 18 feature.
2. Add the five schemas, revokes, and `operations` table.
3. Add stable `MdmError` codes and convert errors only at the SQL boundary.
4. Add the capability adapter and its disabled-capability behavior.
5. Add packaging, the PostgreSQL 18 end-to-end image, and CI.
6. Archive the generated 0.1.0 install SQL and run the static security check.
7. Write installation and grant examples in `README.md`.

## Test matrix

| Level | Case | Expected result |
|---|---|---|
| Unit | Parse the two expected capability rows | Both versions and disabled states are preserved |
| Unit | Missing, duplicate, malformed, and unknown-major rows | One stable `MdmError` per case |
| Unit | Operation state transitions | Only `running -> succeeded` is accepted |
| Package | Build with `cargo pgrx package --pg-config <path-to-pg18-pg_config>` | A loadable PostgreSQL 18 package is produced |
| End to end | Install `pg_mdm` after pinned `pg_trickle` | All five schemas and `operations` exist |
| End to end | Install without `pg_trickle` | PostgreSQL rejects the missing extension dependency |
| End to end | Query v0.98 capabilities | Both expected rows are present and disabled; install succeeds |
| End to end | Attempt Graph V1 work through the adapter | The adapter blocks before upstream mutation |
| End to end | Set `search_path` to an attacker-owned schema | Qualified internal calls still reach extension objects |
| End to end | Use unprivileged, configured, steward, reader, and admin test roles | Each role can perform only its granted operations |
| End to end | Raise an error through a fixed-path helper | `session_user`, `current_user`, `search_path`, and function-local settings are restored |
| End to end | Insert an operation inside a rolled-back transaction | No operation row survives |
| Static | Scan `SECURITY DEFINER` declarations and owners | Every declaration has the required path, no login or superuser owner, no default `PUBLIC` grant, and no unqualified dynamic SQL |
| Static | Scan source for private `pg_trickle` names | No private catalog, buffer, frontier, or generated column is referenced |
| Conformance | Run positive Graph V1 cases on disabled v0.98 | Cases report a capability skip, not a pass |
| Conformance | Run negative Graph V1 admission cases | Every case fails before graph work |
| Test report | Summarize capability cases | Passed, failed, blocked, and skipped counts remain distinct |

## Exit criteria

- [ ] `CREATE EXTENSION pg_mdm` succeeds on the pinned PostgreSQL 18 and `pg_trickle` image.
- [ ] Installation fails cleanly when `pg_trickle` is absent.
- [ ] Graph V1 and Delta V1 disabled states do not fail installation.
- [ ] Every negative capability case returns its documented stable code.
- [ ] No source or SQL file names a private `pg_trickle` relation or provisional API.
- [ ] The hostile-`search_path`, privilege, rollback, package, and negative conformance tests pass.
- [ ] CI runs formatting, linting, unit, pgrx, end-to-end, security, and upgrade-path checks.
- [ ] The generated 0.1.0 SQL archive matches the packaged SQL byte for byte.
- [ ] The package records the exact `pg_trickle` artifact version and image digest used by CI.
- [ ] Every introduced table is marked durable or derived, and every durable table is registered for logical dump.
- [ ] Test reports never count a skipped or blocked capability case as passed.

There is no earlier `pg_mdm` release to upgrade from. v0.1 proves migration-path validation and archives the 0.1.0 base. The first live `ALTER EXTENSION UPDATE` test belongs to v0.2.

## Deferred

Do not add entity catalogs, constructors, graph creation, background workers, custom roles, more PostgreSQL majors, or Delta V1 support. Add them only in the roadmap release that owns them.
