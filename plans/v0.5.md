# v0.5 implementation plan: evidence and pair decisions

## Outcome

Evaluate exact and bounded fuzzy evidence for every discovered pair, apply the V1 precedence table, and produce a deterministic automatic edge order. Execute production-generated evidence SQL through a frozen terminal schema and production reader. Store durable steward `MATCH` and `NOT_MATCH` decisions with optimistic concurrency and complete contradiction checks.

This release returns review facts from pair evaluation but does not publish a review queue. Review persistence belongs to v0.7.

## Prerequisites and dependency changes

Start from v0.4 with complete candidate pairs, normalized values, source authority, evidence groups, lineage, and fixed input-length limits.

Add no runtime dependency. Implement bounded Levenshtein distance with two rows of integer storage, then convert it to an integer score from 0 through 10,000. Do not use floating-point arithmetic or a fuzzy-string crate.

The intended implementation comment is:

```rust
// ponytail: O(n*m) fuzzy comparison, replace it with a bounded bit-parallel
// implementation only if comparator CPU dominates supported workloads.
```

Add the 0.4.0 to 0.5.0 migration, archive the 0.5.0 install SQL, and keep all earlier upgrade starts in the matrix.

## Schema skeleton

Add a decision epoch and one history-preserving decision ledger:

```sql
ALTER TABLE mdm_internal.entities
    ADD COLUMN decision_epoch bigint NOT NULL DEFAULT 0;

CREATE TABLE mdm_internal.steward_decisions (
    decision_id uuid PRIMARY KEY DEFAULT uuidv7(),
    entity_id uuid NOT NULL REFERENCES mdm_internal.entities(entity_id),
    left_source_record_id uuid NOT NULL,
    right_source_record_id uuid NOT NULL,
    decision text NOT NULL CHECK (decision IN ('MATCH', 'NOT_MATCH')),
    decision_version bigint NOT NULL CHECK (decision_version > 0),
    reason text NOT NULL CHECK (length(btrim(reason)) > 0),
    created_by_name text NOT NULL,
    created_at timestamptz NOT NULL DEFAULT statement_timestamp(),
    supersedes uuid UNIQUE,
    is_current boolean NOT NULL DEFAULT true,
    CHECK (left_source_record_id <> right_source_record_id),
    CHECK (supersedes IS NULL OR supersedes <> decision_id),
    UNIQUE (entity_id, left_source_record_id, right_source_record_id, decision_version),
    FOREIGN KEY (entity_id, left_source_record_id)
        REFERENCES mdm_internal.source_records(entity_id, source_record_id),
    FOREIGN KEY (entity_id, right_source_record_id)
        REFERENCES mdm_internal.source_records(entity_id, source_record_id)
);

CREATE UNIQUE INDEX steward_decisions_one_current_pair
    ON mdm_internal.steward_decisions (
        entity_id,
        left_source_record_id,
        right_source_record_id
    )
    WHERE is_current;
```

The API orders pair endpoints by the durable source sort key before insertion. A deferred constraint trigger requires every `supersedes` value to name the prior version of the same entity and canonical pair, allows at most one successor, and requires `is_current` exactly when no successor exists. This one-way history avoids the bidirectional foreign-key cycle that breaks clean logical restore ordering. Direct table access stays permanently revoked, so reversed rows cannot bypass the invariant. Upgrade and privilege tests must fail if any non-extension role gains direct DML access.

To replace a decision, mark the old row non-current, insert the new current row with `supersedes = old.decision_id`, and increment `decision_epoch` in one transaction. The deferred trigger validates the complete chain at commit, and the partial unique index remains enforced. Keep the old row for explanation. Register the ledger with `pg_catalog.pg_extension_config_dump()`. Initial creation uses `expected_version = 0`; replacement requires the current decision version.

## Evidence skeleton

Use these internal result shapes:

```rust
pub(crate) enum EvidenceClass {
	Agree,
	Disagree,
	NoEvidence,
}

pub(crate) struct EvidenceItem {
	pub rule: String,
	pub evidence_group: String,
	pub class: EvidenceClass,
	pub score: Option<u16>,
	pub comparator: String,
	pub comparator_version: u16,
	pub left_value_digest: Option<[u8; 32]>,
	pub right_value_digest: Option<[u8; 32]>,
}

pub(crate) enum PairResult {
	Prohibited,
	ManualMatch,
	AuthoritativeConflict,
	AutomaticIdentity,
	AutomaticStrong,
	Review,
	NoEdge,
}

pub(crate) struct PairDecision {
	pub pair: CandidatePair,
	pub result: PairResult,
	pub evidence: Vec<EvidenceItem>,
	pub independent_agreeing_groups: Vec<String>,
	pub sort_key: Vec<u8>,
	pub reason_codes: Vec<String>,
}
```

Freeze the generated `pair_evidence_v1` terminal schema and exact comparator dispatch in the compiled artifact. Sort evidence by rule name. Sort evidence groups by UTF-8 bytes. Full normalized values and their plain SHA-256 digests are both sensitive. Keep them only in derived relations and protected internal diagnostics; public errors, ordinary logs, and review summaries omit them.

## Comparator contract

Ship two comparator versions:

| Comparator | Result |
|---|---|
| `exact_v1` | `Agree` when canonical bytes are equal, `Disagree` when both values exist and differ, otherwise `NoEvidence` |
| `normalized_levenshtein_v1` | Integer similarity `floor((max_len - distance) * 10000 / max_len)` over Unicode scalar values; empty versus empty is 10,000 |

The definition stores the fuzzy agreement threshold as an integer from 0 through 10,000. Values at or above the threshold agree. Values below it disagree. Candidate generation always runs first; fuzzy comparison never discovers a pair.

Bound both string lengths with the v0.3 cleaner limit before allocating the dynamic-programming rows. Use checked multiplication and return a resource error when the configured work ceiling is exceeded.

Expose one public steward function:

```sql
    operation_id uuid,
    decision_id uuid,

    decision_epoch bigint

```

Require explicit `EXECUTE` grants. Capture the invoking role before entering security-definer code. Lock the entity row and the current pair decision before validating `expected_version`.

### Pair-decision precedence

Apply this precedence to each candidate pair:

1. An effective current `NOT_MATCH` returns `Prohibited`.
2. An effective current `MATCH` returns `ManualMatch`, even with an authority conflict.
3. Different valid authoritative identity values return `AuthoritativeConflict` and a review fact.
4. One agreeing identity rule returns `AutomaticIdentity`.
5. One agreeing strong rule returns `AutomaticStrong`.
6. One or more agreeing supporting groups return `Review` with reason `SUPPORTING_ONLY`, but never an edge.
7. Everything else returns `NoEdge`.

Count an evidence group once. The compiler has already ensured that independently counted groups have disjoint normalized lineage.

For automatic edges, serialize a total sort key in this order:

1. Identity before strong.
2. More independent agreeing groups before fewer.
3. The fixed ordered evidence vector, with greater scores first.
4. The canonical left and right source sort keys.

Document the binary format and version it as pair-decision policy 1.

## Contradiction checks

Validate all current directives over durable source records, including records that are currently inactive. A current decision is `effective` when both endpoints are active and `dormant` otherwise. Dormant decisions take part in write-time global contradiction validation but not active clustering. A non-current row is `historical`. This prevents a later reactivation from revealing an accepted contradiction.

- Before `MATCH(A, B)`, compute the manual-match components containing A and B. Reject the write if any current `NOT_MATCH` crosses the proposed merged component.
- Before `NOT_MATCH(A, B)`, reject the write if A and B already share a manual-match component.
- Before replacing a decision, evaluate the graph as it would exist after the old row is marked non-current and the new row is inserted.
- If a configured closure limit prevents a complete check, reject the write with `MDM_DECISION_CHECK_LIMIT`.

Return a bounded contradiction path containing decision IDs and source-record IDs. The path is diagnostic only; the complete check must finish before a write succeeds.

## Exit criteria

- [ ] Exact and fuzzy comparator outputs match all committed vectors without floating-point arithmetic.
- [ ] Every candidate pair receives one deterministic result and ordered evidence list.
- [ ] Generated evidence SQL and the production reader match independently constructed terminal expectations.
- [ ] Manual decisions, authority conflicts, identity, strong, and supporting evidence follow the documented precedence.
- [ ] Automatic edge ordering is total and invariant under input and plan reordering.
- [ ] `MATCH` and `NOT_MATCH` writes preserve a globally coherent manual-constraint graph.
- [ ] Optimistic concurrency, supersession history, actor, reason, operation ID, and decision epoch are durable.
- [ ] Clean logical restore preserves current and superseded decision meaning without circular foreign keys or database-local actor OIDs.
- [ ] The internal domain report records pair errors and review volume against committed thresholds.
- [ ] A closure or comparator resource limit fails before a decision is committed.
- [ ] No evidence or pair-result production table exists.
- [ ] Upgrade tests and the complete v0.1 through v0.4 matrices pass.

## Deferred

Do not add weighted scores, learned models, floating thresholds, custom SQL comparators, universal disagreement vetoes, direct merge or split actions, bulk decisions, or review persistence.
